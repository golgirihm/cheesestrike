# CheeseStrike: Gouda Overload

A multiplayer first-person shooter for Steam, made with Unreal Engine 5.8 in C++. The cover is cheese, and a minute into every match giant mice come and eat it. [docs/unreal/design.md](docs/unreal/design.md) is the whole game as a specification, and [docs/unreal/spike.md](docs/unreal/spike.md) is the plan the project is being built by. The game was first made in Godot; that version is kept at the `godot-final` tag, and its code there is the reference wherever the design document is not enough.

The project is at the repository's root: `CheeseStrike.uproject`, `Source/CheeseStrike/` (one game module), `Config/`, and `Content/`, which is the private `cheesestrike-assets` repository as a git submodule (see below). It began as Unreal's First Person template with its Shooter variant; `Config/DefaultEngine.ini` redirects the template's script package and classes to ours, and fixes two mistakes in the template's own content. The template's shooter level is the playground until the game has arenas of its own; its game mode override is cleared, so it plays with the game's own character, and its weapons, pickups and enemies are the template's and don't yet work with it.

## What the port keeps

The Godot game is the source of the design, not a thing to copy. Keep what Unreal and its First Person template do well (their input, movement feel, camera, scale and conventions) and port the game's ideas and tuning where they matter: the cheese that is cover and gets eaten by the mice that come partway through a match, so that a map opens up and the fight intensifies; the weapons' roles and roughly their numbers; the modes; the Overload. Don't port the Godot key bindings, speeds, scale or maps for their own sake. Words: a player is killed and scores kills, never knocked out. The Godot maps were placeholders; a placeholder map (the template's shooter level) does until there is a plan for how levels work.

## Testing rules

Every change follows both of these, in the same pull request as the change:

1. **Automated tests.** Assess whether the change's behavior can be covered by an automated test. If it can, write the test with the change. Tests are Unreal Automation tests in `Source/CheeseStrike/Tests/`, named `CheeseStrike.<Area>.<What it checks>`. Rules belong in plain C++ that a test can call without a world, as the Godot game kept its rules in plain classes. What needs the game running gets a test that plays it in the editor (`CheeseStrike.Play.*`, through `Tests/PlayTesting.h`): alone, or as a host with joiners in the same process for anything networked, each player driven by a play script (the same commands as `tools/play.ps1` uses) and the result read off the characters and the match state. Such a test takes ten to twenty seconds, so put several checks in one.
2. **Manual tests.** Assess whether `docs/manual-tests.md` needs rows added, changed or removed. Behavior that an automated test can't cover gets a row. A row that becomes covered by an automated test is deleted.

Say what you concluded in the pull request description, including when the answer is that no test or no manual-test change was needed.

Before pushing, run the tests: `python tools/run_tests.py`, which builds the editor and runs every `CheeseStrike` test headless, or `python tools/run_tests.py CheeseStrike.<Area>` for some of them. It fails if no test ran.

To see a change in the game itself, play it without a person: `powershell -ExecutionPolicy Bypass -File tools/play.ps1 -Script tools/play/<script>.txt -Tag <name>` starts the game rendering offscreen (no window, and the person at the PC keeps their mouse and keyboard; the editor must be closed), plays the script's commands through injected input (`Source/CheeseStrike/Dev/CheeseStrikePlayScript.h` lists them: hold and release actions, look, screenshot, state, a console command such as `CheeseStrikeDie`, quit), saves screenshots to `Saved/Screenshots/WindowsEditor/`, and traces the character's state ten times a second into `Saved/Logs/<name>.log` (`-TraceState`). `-ClientScript` starts a second game that joins the first, for two players, named by `-Name` and `-ClientName`; `-Extra "?listen?KillLimit=1"` passes the host's options. Read the numbers first (speed, eye height, crouched, health, ammunition, shots and hits), then the pictures. Write a script for what a change needs (the ones in `tools/play/` are examples), and give it `-StartAt X,Y,Z,Yaw` for a spot with room. The template's first-person rifle sits large and low in the view, so a thing on the floor ahead is often behind it: look to the side to see it.

## Working in this repo

- **Pull requests only.** `main` is protected: changes arrive through a pull request, merged by rebase. Keep each commit on a branch meaningful, since every one lands on `main`.
- **After merging, move on.** Once a pull request's checks have passed on an up-to-date branch, merge it and carry on.
- **Delete the local branch after merging.** A rebase merge rewrites the commits, so git won't see the branch as merged and `git branch -D` is needed. Return to an up-to-date `main`.
- **No AI attribution.** Don't add "Generated with Claude Code" to pull request descriptions or a `Co-Authored-By` trailer for Claude to commits.
- **C++ first.** Gameplay is written in C++ so that it can be read, edited and reviewed as text. Blueprints are for wiring assets to C++ classes (meshes, sounds, animation, the values a designer tunes), not for logic. A Blueprint can't be read in a diff, so say in the pull request what changed in one. Input actions and key bindings are made in code too (`Source/CheeseStrike/Input/`), not kept as assets. Assets the C++ needs (meshes, animation Blueprints) are found by path in constructors.
- **The menus are Slate in code.** `SCheeseStrikeMenu` (`Source/CheeseStrike/UI/CheeseStrikeMenu.h`) draws the front end, the matches found, the lobby (where the host sets the rules, and everyone sees who is in), the pause menu and the options, with its icons and the lobby's tile from `Content/UI/`; which page shows follows the match's state (`CheeseStrikeMenu::PageFor`, run each tick by the player controller), not clicks. While a page shows, only the menu takes input: the character ignores its player's (`ACheeseStrikeCharacter::TakesInput`), so a paused player can't move or fire, the options opened from the pause menu included; the game goes on behind them (alone too), blurred and darkened by an `SBackgroundBlur` (`CheeseStrikeMenu::PauseBlur`, `IsBlurringTheGame`). Each page is drawn again only when something on it changes (`LobbyKey`, `PageKey`, checked every frame), so that its spinner turns on unbroken and a slider being dragged stays; the seconds count down by themselves. The lobby's rules are rows of dropdowns (`MakeDropdown`, an `SMenuAnchor` in the current window, styled as the menu; a joiner sees the host's choices in plain boxes, `MakeReadOnly`), so that the whole lobby fits a 16:9 screen with no scrolling (`CheeseStrike.Play.EveryoneEntersTheMatchTogether` measures it at 1280x720, 1600x900 and 1920x1080); while the host has one open the lobby isn't drawn again (`CheeseStrikeMenu::ShouldRedrawLobby`), unless its status changes, and `CheeseStrikeDropdown <n>` opens one for screenshots (`tools/play/ui_polish_server.txt`). Hosting and joining show a spinner and take no more clicks until the level they lead to has loaded or they fail (`UCheeseStrikeSessionSubsystem::GetPending`). The lobby's columns are the sides, eight seats each: the players, the bots that will stand in, then open seats, each a chip in its side's colour (`CheeseStrikeMenu::TeamColour`; `CheeseStrikeRules::WithEmptySeats`); `MakeSeatColumns(bTeams)` draws them, or one column of every seat for a free-for-all. What the lobby's bottom says is `CheeseStrikeMenu::LobbyStatus`: a joiner's lobby says "Joining the lobby" until the host's match has come with the host and the joiner in it, and a joiner the server tells to travel shows where to at once (`PreClientTravel`), and goes on showing it (not the front end) once the connection to the level being left has closed. A player is in a match only in a level with a connection of its own: while joining, the engine calls the level left behind a client. Each second of the countdown sounds a soft tone and its end a brighter chime, on every player's machine (`CheeseStrikeTones`, made in code, `SoundCountdown`). After every level load a cover in the lobby's looks stays up until the view is ready (`UCheeseStrikeCurtainSubsystem`, `IsViewReady`): a joiner otherwise sees the engine's view from the world's origin before their controller and character come. While the match travels to another level (the map the host picked, or back to the lobby after the results), the lobby shows, saying where to. Travel URLs are the map and the options only (a URL naming the port is refused), and a travel keeps any option of the last URL the new one doesn't name (a joiner following the server drops the host's `?Nick=` from the server's URL, keeping their own: `ClientTravelInternal`), so the rules' options always carry every value (`?Bots=-1`, `?Players=0`). Hosting goes straight into the lobby with the usual rules, seven bots (`CheeseStrikeRules::DefaultBots`) and the first map; the host picks the map there (`CheeseStrikeRules::Maps`), and when the match starts everyone travels to it (`?Players=`) and it begins when every player's machine has said its level is loaded and its view can be shown (`ServerReady`, `CheeseStrikeRules::ShouldBegin`), or after `WaitForPlayers` seconds for anyone who never comes: until then everyone, the host too, stays behind the cover, which says how many are ready, and the bots come in as it begins. A match waits in the lobby (`AGameMode`'s delayed start) until the host starts it, with the design's five-second countdown, and `RestartGame` brings everyone back to the lobby ten seconds after the results. `?StartNow` on the URL skips the lobby: `tools/play.ps1` and the play tests use it unless told to use the lobby (`-Lobby`, `FSession::bLobby`).
- **The options are the engine's settings, made the game's.** `UCheeseStrikeSettings` (`Source/CheeseStrike/Settings/`) is the engine's `UGameUserSettings` (`Config/DefaultEngine.ini` names it), kept in `GameUserSettings.ini`: the graphics (quality preset, window, resolution, VSync, frame rate limit, as the engine applies them; not the window in the editor), and the game's own, each applied as it is set: the look's sensitivity, its share while aiming and inverting it (`ACheeseStrikePlayerController::LookScale`, used by the character's `DoAim`; a play script looks as the usual settings would), the field of view from the top of the view to the bottom, 75 by default as in the design (the camera manager turns it into the engine's across, for the screen's shape), and the master and effects volumes (`ApplySound`: the audio device's volume, and a sound mix over every sound class but the menu's, run again after each level loads). The options' rules (ranges, the field of view across, the resolutions offered) are `CheeseStrikeSettings::*`, tested in `CheeseStrike.Rules.TheOptionsOpenAndKeepToTheirRanges`.
- **Matches go through Steam.** `Config/DefaultEngine.ini` puts the game on the Steam online service (test app id 480) with the Steam net driver; a match is a lobby that `UCheeseStrikeSessionSubsystem` offers, finds, joins and leaves (`Source/CheeseStrike/Sessions/`), driven for now by the console commands `CheeseStrikeHost [?KillLimit=..]`, `CheeseStrikeFind`, `CheeseStrikeJoin <n>` and `CheeseStrikeLeave`. Steam is only used by `-game` and packaged builds with the Steam client running; the editor, the tests and `tools/play.ps1` (unless given `-Steam`) use the Null service, which does the same over the local network, so the flow is tested in the editor and Steam itself is checked by hand on two PCs with two accounts. A second game on the same PC and account never gets the first's lobby data from Steam.
- **The HUD is drawn in code.** `ACheeseStrikeHUD` (`Source/CheeseStrike/UI/`) draws everything over the view on the canvas, in the engine's bold condensed Roboto through a runtime `UFont`, its shapes made of triangles (`CheeseStrikeHUDDraw`), by rules that are plain functions tested without a world (`CheeseStrikeHUDRules.h`, `CheeseStrike.HUD.*`); it draws nothing under the front end and the lobby. The minimap is made from the level itself (`FCheeseStrikeMinimap`: every visible static mesh that blocks players, outlined from above by its collision shapes and shown by its height against the player's, and the cheese as it is now), so a new map needs nothing for it (its doors drawn as they are, open or shut); north is +Y on every map, and the name of the place the player is in (`ACheeseStrikePlace::NameAt`) shows under it, as the place a body fell does in the kill feed. A hit reaches the hurt player's machine through `ACheeseStrikeCharacter::ClientHurtFrom`. Who is on whose side is the mode's (`ACheeseStrikeHUD::AreTeammates` asks `ACheeseStrikeGameState::AreTeammates`), the minimap shows every enemy while the side's Unmanned Aerial Cheese is up (`IsRevealedTo`, or `RevealEnemies` on this machine), health is a cross and a row of blocks, never a number, anywhere (`HealthFills`, red and breathing when low with the red edges, what a hit took lingering a moment), the score at the bottom is `ScoreSummary` (a free-for-all's or the sides' and the round), the list over the ammunition is `WeaponSlots` (the inventory's), and a player out of the round (`ACheeseStrikePlayerState::IsOut`) is struck through in the row, and a player down in Execution washed and framed in red-orange, "DOWN" across the tile and the strip under it running down as they bleed out (`CheeseStrikeHUD::EStatus::Down`), and marked "DOWN" on the scoreboard; the modes' own announcements, streaks and being out are `CheeseStrikeModeHUD`'s, drawn into the same canvas in the same look; a side's colour is `CheeseStrikeModes::TeamColour` everywhere. In the game (not the editor) the engine's own messages on the screen (debug messages, the map's and the renderer's warnings) are kept off the player's screen, and video memory running out is written to the log; the texture streaming pool is sized to what the maps need in `Config/DefaultScalability.ini`. Steam profile pictures come through the Steamworks API (`UCheeseStrikeAvatars`), only when the game is on Steam; otherwise initials. For judging it from screenshots: `CheeseStrike.HUD.MeltAt`, `CheeseStrike.HUD.Health`, `CheeseStrike.HUD.HoldArcs` with `CheeseStrikeHitFrom <degrees>`, and `CheeseStrikeReveal`, in `tools/play/hud*.txt`.
- **Animation is composed in code.** `UCheeseStrikeAnimInstance` (`Source/CheeseStrike/Animation/`) builds the body's pose from the engine's standalone animation nodes (sequence and blend-space players, blends, mesh-space additives for the aim offsets, a slot for firing and reloading) and reads what the character is doing each frame; no animation Blueprint, so every machine's copy of a character animates alike and a new rig is a change of asset paths. Only nodes without folded properties are safe this way (the `_Standalone` players, `FAnimNode_TwoWayBlend`, `FAnimNode_MultiWayBlend`, `FAnimNode_ApplyMeshSpaceAdditive`, `FAnimNode_Slot`); the ordinary blend-space player, aim-offset and blend-by-bool nodes read Blueprint-only data and would fail in a packaged game. The rifle and its sounds are Lyra's (`Content/Characters/Heroes/`, `Content/Weapons/Rifle/`, `Content/Audio/`; `Content/LICENSES.md`), copied from the Lyra sample with their dependencies; the rifle is modelled along its Y axis and is turned a quarter turn in the hand bone `weapon_r`. The body, which others see and whose arms its own player sees (the first-person body is the same mesh and animation, its head hidden from its player and the camera just under its eyes, `FitFirstPersonBody`), is a Paragon hero: `CheeseStrikeBodies` (`Source/CheeseStrike/Animation/`) is the table of them (Lt. Belica, Murdock, Twinblast and Wraith, `Content/Paragon*/`) and says which a player has. In a mode with sides, each side has two heroes whose palettes go together, the Gouda Guys Murdock and Twinblast, the Mozza Radicals Belica and Wraith, worn by the players of a side in turn (by player id) and dressed in the side's colour, as the lobby and the HUD show it (`CheeseStrikeMenu::TeamColour`), on their armour (material instances in each hero's `Materials/Teams/`, made by `tools/art/team_looks.py`); in a free-for-all each player has one of the four in turn, in its own colours. The character puts on its player's every frame it lacks it (`UpdateBody`, from the replicated sides and ids, so every machine agrees; a fallen body keeps the one it fell in), and `CheeseStrikeBody <n> <side>` shows any of them, for looking (`tools/play/bodies.txt`). A hero comes from the Lyra project, where the user adds Paragon packs through the Epic Games Launcher: `tools/art/lyra_hero.py` (run there, holding the Lyra lock) retargets Lyra's rifle set to it through Lyra's UE4-mannequin IK rig, which fits every Paragon hero's bones, with the pistol, shotgun, melee and draw animations the other weapons are held by (`weapons` does only those, through the retargeter already made), and lists what it needs; `tools/art/copy_from_lyra.py` copies that in; `tools/art/fit_hero.py` (`animations` for the animations alone) strips Lyra's animation modifiers, cuts the textures to 1024 and drops the retargeted animations' tracks for bones the reference pose scales (Belica's face hangs from `faceAttach` at 0.79, and at 1 her eyes and lips swell; the animation also keeps those bones at that scale). One animation class plays them all (`UCheeseStrikeHeroAnimInstance`, which plays its mesh's skeleton's sets, the one for how the weapon in hand is held). The heroes' `weapon_r`, where they have one, stays where their own guns were, so the rifle rides `hand_r` at each hero's grip (`ACheeseStrikeWeapon::PutInHand`, turned as the mannequin's `weapon_r` holds it in the same frame of the idle, `tools/art/measure_bodies.py`), and their own guns are hidden (their material slots, or Belica's gun bones). Murdock's first-person body also hides his chest and helmet, which come before his eyes as he aims. To look at the body with one game, `CheeseStrikeOutside <distance> <yaw>` puts the view outside it (`tools/play/body.txt`); with two, the joiner starts 4 m from the host, facing it. The left hand is held on the rifle by `FCheeseStrikeGripIK`, at the grip the idle pose gives it relative to `weapon_r`, rather than by the animations' `ik_hand` bones, which the aim offsets leave behind. Firing and reloading play from the spine up (`FAnimNode_LayeredBoneBlend`), the legs walking on; the locomotion pose that feeds both is evaluated twice but updated once (`FCheeseStrikeSharedPose`), since a native graph has no cached poses. A player down in Execution's last stand lies on their back, posed last, in component space, by `FCheeseStrikeDownedPose` (`Animation/CheeseStrikeDownedPose.*`), from the crouched pistol set and by the mannequin's bone names every hero has (`CheeseStrikeDowned::PoseBones`, checked in `CheeseStrike.Animation.EveryBodyIsComplete`): the chest squared to the hips, the pelvis laid back on the floor where `CheeseStrikeDowned`'s rules (`Rules/CheeseStrikeDowned.h`) have the hips, the spine curled up and the torso turned about the hips until the left shoulder is an upper arm over the floor (propped on that elbow, by two-bone IK), the chest turned toward an aim to the side, the head looking along the aim, the pistol hand out along it from the right shoulder (for the first-person body, from the eyes, so that the arm never crosses the view), the legs out ahead along the floor by two-bone IK as far as there is room (`ACheeseStrikeCharacter::MeasureLegRoom`, a sweep ahead of the hips; bent up against a wall), pushing in turn as the body scoots or turns round, and a laboured breath; it is blended in over `CheeseStrikeDowned::Seconds` and out over `RiseSeconds`, bone by bone in local space, so going down and getting up don't snap. The first-person body plays it too, so the view (on its head, a little ahead of the face) sits low, about 40 cm up, looking past its own legs, drawn at the world's field of view while down so that the legs lie on the floor in view, the arm it is propped on hidden; the arms are left where the pose has them (no hip hold, no aiming down the sights). Aiming down the sights moves the first-person arms, not the camera: each frame they are placed so that the rifle's sight line runs down the view through the eye (`BringRifleToEye`), and shots leave from the eye along the view. Each hero's ragdoll is `PA_<Hero>_Ragdoll`, made by `tools/art/ragdolls.py` (Paragon's own physics assets are rough bounds ones, which as ragdolls float): a body for each part that moves on its own and none under the head (so the face stays on) or for its own guns, every joint on hard limits as a person's (the script's table: hinged knees and elbows, a spine and neck that twist little), damped so that it settles, and the dying character's speed passed to the body; `CheeseStrike.Play.AKillIsScoredAndTheKilledComeBack` checks the body comes to rest within those limits on both machines. `tools/play/ragdoll.txt` watches a body die four ways (with `-FixedFps 30`, so that a busy PC doesn't show the fall in slow motion).
- **Maps are built by scripts.** A map is a Python script in `tools/art/` that builds its level from nothing in the editor (`build_creamery.py` for The Creamery, with `build_materials.py`, `cheese_material.py` and `wax_material.py` for its materials), so a map can be read and changed as text; its notes are in `docs/unreal/maps/`, and [docs/unreal/maps/principles.md](docs/unreal/maps/principles.md) is how to design and build one. The scripts are built from `tools/art/map_kit.py`: ground, walls, ramps, stairs, props, cheese in blocks, walls, floors and stacks, buildings of several storeys, tunnels, bridges, doors (`ACheeseStrikeDoor`, which open as anyone comes up to them), starts, the mice's ways in, named places (`ACheeseStrikePlace`), the navigation bounds and the light; `build_level` builds, checks and reports. `tools/art/map_picture.py` takes a map's picture for the lobby. Its art is free Fab content: Fab's web page downloads a listing's files (a Megascans surface's texture set, a model's FBX), kept outside the repository in `C:\Hamid\code\FabDownloads`, and `import_fab.py` imports what the maps use into `Content/Fab/` (box collision, Nanite, textures cut to 2K or 1K); a listing that only comes in Unreal's own format needs the Epic Games Launcher, which a script can't drive. Surfaces are drawn on the maps' blocks from world space (`M_Surface`); a model that stands for cover is scaled to fill its block. Every block of cheese is an `ACheeseStrikeCheese` (`Source/CheeseStrike/Map/`) naming the structure it belongs to, for the mice to eat. A script that saves a level must check the level it has open: the editor opens on the shooter level, and a failed open builds into that.
- **Weapons are numbers in code.** Every weapon is a plain `FWeaponStats` in `Weapons/CheeseStrikeArsenal.cpp` (the design's table, its lengths divided by three; tested in `CheeseStrike.Weapons.*`), with the lists the game is played by (the primaries, Gun Game's ladder). Every character carries a primary (the Cheddar Blaster unless its player chose another with `CheeseStrikeLoadout <weapon>`, which takes effect at the next life, or at once just after coming in), the Curd Pistol and the Cheese Knife (`UCheeseStrikeInventory`, a component of the character's): the server spawns each as its own `ACheeseStrikeWeapon`, with its own rounds, and every machine shows only the one in hand. Changing (1, 2, 3, the wheel, Q) happens at once on the player's machine and is asked of the server through the weapon being drawn, so that its shots arrive after it; a weapon fires only once its draw time is past, there and on the server. A mode changes what a character carries on the server (`Give`, `GiveOnly`, `RestrictTo`, `HoldNow`), in its `SetPlayerDefaults` or when it likes. The knife strikes rather than fires: a stroke swept a little either side of the aim, decided on the server as shots are, deadly in the back, with a lunge that goes through the saved moves, as a heavy weapon's slowing does. Shots are heard whole by the shooter and, by everyone else, from where they were fired, fading and growing duller with distance and only so many at once (`CheeseStrikeGunfire`; Lyra's sound waves carry no attenuation of their own); `CheeseStrike.TraceGunfire 1` logs each. Each weapon's look is a row of `CheeseStrikeWeaponLooks` (`Weapons/CheeseStrikeWeaponLooks.cpp`): its model (Lyra's rifle, pistol and shotgun; Fab's PPSh-41, DP-28, SV-98 and M4, imported by `tools/art/import_weapons.py`; the Cheese Knife and the muzzle flash, made by `tools/art/weapon_models.py`) placed in the rifle's grip frame, its materials, sounds, sights, muzzle and where the left hand holds it. The weapon loads them by path as it becomes that weapon, so that the scripts can rebuild them, and their folders are in `DirectoriesToAlwaysCook`. The cheese is one material, `M_CheeseWeapon` (`tools/art/weapon_materials.py`), which turns the parts a mask names (a Fab gun's wood, masked by `tools/art/weapon_textures.py`; a Lyra gun's painted panels) or a box in the model's own space into mottled, holed, veined or waxed cheese, in that space so that it moves with the weapon; cheese lighter than the arena's reads as white plastic. The HUD's pictures of the weapons are side views drawn by `tools/art/weapon_icons.py`. Each way of holding (`ECheeseStrikeHold`: rifle, pistol, shotgun, knife) has its animations on every hero (`UCheeseStrikeAnimInstance::FindSets`; a hold a body has none for plays its rifle set). At the hip the first-person arms are moved and turned so that the hand holding the weapon stays where its hold has it in view (`CheeseStrikeWeaponLooks::HipHand` and `HipAlong`, measured with `tools/play/hip_measure.txt`): Lyra's crouched and moving poses bring the weapon up towards the eyes, which would fill the view. A scoped weapon, aimed, hides the arms for the HUD's scope. `CheeseStrikeArm <weapon>` puts any weapon in hand at once (not in shipping builds); `tools/play/weapon_looks.txt`, `weapon_heroes.txt` and `pistol_view.txt` look at them.
- **Bots are played in code.** `ACheeseStrikeBotController` plays a bot on the server, by the rules in `Rules/CheeseStrikeBots.h` (the design's skill table, aim error that steadies as it tracks, turning no faster than its skill, bursts and rests, a sight cone, keeping to its weapon's range), tested without a world in `CheeseStrike.Bots.*`. It sees by line traces, walks the navigation mesh (`Config/DefaultEngine.ini` builds it when a level starts, in the level's `NavMeshBoundsVolume`, and rebuilds it where the level changes), and works its character as a player does: path following and movement input, its control rotation for the view, the character's `Do*` actions for the trigger, the sights, reloading and changing weapons (a primary suited to its skill, the pistol when the magazine runs out with someone near, the knife up close: `CheeseStrikeBots::ChooseWeapon`); the weapon aims a bot's shots by its control rotation. No behaviour tree or blackboard assets. The host picks the skill in the lobby (`?BotSkill=`). Play tests get no bots unless they ask for them (`?Bots=` in `FSession::Options`); `tools/play.ps1 -Bots` fills a match with them.
- **The mice eat the cheese.** A minute into a match (`?MiceAt=` for sooner, `?Mice=0` for none) the game mode sends in one mouse for every sixty blocks of edible cheese, two to eight, at the level's `MouseEntry` points (on top of its edge, facing in; a map without them or without cheese has none). `ACheeseStrikeMouse` (`Source/CheeseStrike/Map/`, by `Rules/CheeseStrikeMice.h`) runs on the server: it goes for the cheapest block (distance, plus four times its height, plus more for another mouse's), walks the navigation mesh to a spot beside it (never on top of it) with its own path following (finding its way afresh every few seconds, and when it has fallen) and keeps to the ground (falling when what it stood on is eaten), eats 40 every half second, runs from shots that hurt it by 300, and gives up on a block it makes no progress on. It blocks nothing but shots (its box blocks only the visibility channel), which reach it as the engine's point damage. Its body is the Black Rat from Fab, played by single animations (walk, run, sniffing to eat) chosen by a replicated state, and every machine plays its sounds by that state too (gnawing and crunches while it eats, squeaks now and then, a scream as it runs; from OpenGameArt, pitched down for its size). `ACheeseStrikeCheese` replicates (dormant until bitten or falling), shows its stage of being eaten in its mesh's custom primitive data (the cheese material's holes grow), and when eaten or falling makes what rested on it fall unless what else is under it holds it (`CheeseStrikeMice::IsHeld`: its middle inside what it rests on), down until it comes onto something that does. Cheese a map marks not edible (its walkable way through, round its starts) is never eaten, and wears red wax; every map in `CheeseStrikeRules::Maps` is checked to keep its starts on the ground and joined once the mice have eaten everything else (`CheeseStrike.Play.AfterTheMice`). The console's `CheeseStrikeCheeseLeft` counts the cheese left and `CheeseStrikeUnheld` lists any standing on nothing. Play tests and `tools/play.ps1` have no mice unless asked for (`?Mice=` in `FSession::Options`; `-Mice`). `CheeseStrikeMice` logs every mouse. A map may have a drop that kills (The Fondue Floor's vat of fondue): its kill height (`kit.kill_below`, World Settings' KillZ) kills whoever goes under it by the fall (`ACheeseStrikeCharacter::FellOutOfWorld`, `Rules/CheeseStrikeFalls.h`), the kill going to whoever hurt them in the five seconds before, else the feed and the death screen saying how ("fell into the fondue", from the place they fell into); there the bots never walk off an edge, a mouse never walks off one nor eats the floor from under itself or another mouse, leaps across a gap when it has eaten the floor round itself, and one that falls in anyway comes back over the edge a while later, and cheese that sinks under it is gone. The console's `CheeseStrikeEatCheese <share> [structure]` eats a share of the cheese at once, for looking at a map as the mice leave it.
- **Modes and streaks.** A match is played in the mode on its URL or picked in the lobby (`?Mode=FreeForAll`, `Deathmatch`, `Elimination`, `Execution` or `GunGame`; `CheeseStrikeModes` in `Rules/CheeseStrikeModes.h` says what each is, how it is won, who takes a round and who may hurt whom, tested without a world), which the game state tells everyone (`ACheeseStrikeGameState::GetMode`, `HasTeams`). Every player has a side (`ACheeseStrikePlayerState::GetTeam`); only a team mode uses it: the teams' scores (`GetTeamScore`), friendly fire off (`ACheeseStrikeGameMode::CanHurt`, asked by the character's `TakeShot` and `TakeBlast`), bots that fight only the other side, and each side coming in at the starts the map tags for it (`PlayerStartTag` "Gouda" or "Mozza", as The Creamery's are) or else at its half of them. Elimination is rounds of one life each (`?Rounds=`, `?RoundTime=`): the killed are out (`IsOut`) and watch a teammate (`ACheeseStrikeWatchCamera`) until a side is all out or the time runs out, then after a pause everyone comes back at their side's starts. Execution is Elimination with a last stand (`Modes/CheeseStrikeLastStand`, a component of the character): a hit that would kill, once a life, puts a player down instead, with only the sidearm (the inventory's `RestrictTo`), harmed only by an enemy within a couple of metres, and shown on every machine lying on their back, propped on an elbow, the pistol out (`FCheeseStrikeDownedPose`, under Animation), and in the HUD's row and scoreboard as down. Down, the capsule is crouched (it covers the raised head and shoulders; the legs lie out ahead of it, and going down the server moves the body back from a wall just ahead, `MakeRoomToLieDown`); the view is kept to a cone toward the feet (`CheeseStrikeDowned::ClampView`, in `ACheeseStrikeCharacter::FaceRotation` on the machine that controls it, players' and bots' alike) and the body turns round after it slowly (`TurnBody`); it scoots on its back along itself, toward the feet only while the legs have room (`CheeseStrikeDowned::ScootInput` in the movement component's `ConstrainInputAcceleration`, `ScootSpeed`), the sideways keys turning it; the eyes (`Eyes`: shots' head and bots' sight) are at the raised head, and shots find the torso and the legs where they lie (`FHitHistory`'s lying samples, `RayHitsBody`); others see its aim to the side by `DownAimYawSent`; a bot down stays where it lies and fights; held Interact (E) finishes them from an enemy or revives them from a teammate, and left alone they bleed out. `CheeseStrikeDown [name, enemy or mate]` on the host's console puts someone down and `CheeseStrikeRevive [name]` gets them up (`tools/play/downed.txt`, `downed_wall.txt`, `downed_row.txt`). Gun Game moves a player up `CheeseStrikeArsenal::GunGameLadder` at each kill (the weapon in the killer's hand as the shot or stroke lands decides a knife kill, which drops the killed a step), giving the step's weapon, and the knife until the knife is the step, in `SetPlayerDefaults` and at once after a kill; a kill on the last step wins. Kills in a row earn streaks (`Rules/CheeseStrikeStreaks.h`: 3, 5 and 10), kept on the player state until the Streak key (4) calls the next one in (`ACheeseStrikeGameMode::CallStreak`): the Unmanned Aerial Cheese (`Streaks/CheeseStrikeAerialCheese`; the game state's `IsRevealedTo`), the Cheese Strike, marked by the next shot, and the Gouda Overload (both `Streaks/CheeseStrikeBombs`, wheels whose bursts are checked for line of sight and score for the caller); bots call theirs in too. The whistle and the siren are made in code (`Streaks/CheeseStrikeSynth`). What the modes and streaks show over the view is drawn by `UI/CheeseStrikeModeHUD`, which the HUD calls. `CheeseStrikeGiveStreak <1-3> [name or enemy]` on the host's console gives one for looking at it (`tools/play/strike.txt`, `streaks.txt`, `elimination.txt`).
- **Movement is predicted.** Anything that changes how the character moves must reach the server through the saved move (`CheeseStrikeMovementComponent`): a held key as a compressed flag, state as fields saved and restored with the move. Otherwise the server disagrees with what the player saw and snaps them back.
- **Editing assets from a script.** The editor's Python runs headless: `UnrealEditor-Cmd.exe <project> -ExecCmds="py <script>" -unattended -nullrhi` with `unreal.SystemLibrary.quit_editor()` at the script's end (the `-run=pythonscript` commandlet can't save a map). `print` goes nowhere; write to a file. The editor must be closed first: it holds the game module and the open level's file. A script can't rebuild a material that a C++ constructor loads, directly or through what it loads (a mesh's materials and their parents): what is loaded at the editor's start is rooted for good, and deleting its expressions asserts; so a class whose assets the scripts rebuild holds them as soft references and loads them in `BeginPlay` (`ACheeseStrikeMouse`). Setting a slot of an array read with `get_editor_property` changes a copy: build new structs and set the array back.
- **Packaging and sharing.** `powershell -ExecutionPolicy Bypass -File tools/package.ps1` packages a Development build for Windows (`BuildCookRun`; not Shipping, which would have Steam relaunch it as the test app id's game), plays it twice headless to check it (`tools/play/packaged_*.txt`: the menus, then a match on The Creamery with bots and mice), zips it without its debug symbols (kept in `..\CheeseStrikeBuilds\symbols\`) and copies the zip into `G:\My Drive\CheeseStrike Builds`, which Google Drive for desktop uploads, keeping the newest three. Only the maps in `Config/DefaultGame.ini`'s `MapsToCook` are cooked, with what they and the code reach, so a new map goes in that list as well as in `CheeseStrikeRules::Maps`; an asset that C++ holds only as a soft reference or loads by a path built at runtime isn't cooked, so its folder goes in `DirectoriesToAlwaysCook` (the mice's rat and sounds), and files read as files rather than assets (the menu's `Content/UI/`) are staged by `DirectoriesToAlwaysStageAsUFS`. The packaged game compiles as a unity build, so names in one file's anonymous namespace meet every other file's: give them names no parameter will have (`MousePitch`, not `Pitch`), or the package fails where the editor's build didn't.
- **The compiler is pinned.** Both targets in `Source/*.Target.cs` build with MSVC 14.50.35717, which Unreal 5.8 is made for; the 14.51 that Visual Studio 2026 updates bring in breaks the engine's headers. Change it there when Epic supports a newer one.
- **Working on several things at once.** `python tools/worktree.py add <name>` makes another working copy at `C:\Hamid\code\cs-wt\<name>` on a branch of that name, its `Content/` a worktree of the assets submodule (sharing its history and LFS objects; never `git submodule update` there, but `git -C Content checkout <commit>`), and `remove <name>` deletes it. Each copy builds its own binaries, and its tests and played games keep to themselves: `tools/run_tests.py` and `tools/play.ps1` give each copy its own build id (`-BuildIdOverride`, so that matches on the local network are found only by the same copy) and `play.ps1` its own port; play tests in the editor listen on a port of the copy's own too (`PlayTesting.cpp`), since a match that travels listens again on the port it was first given. Close only the games and editors of the copy being worked in.
- **Building from the command line.** `"C:\Program Files\Epic Games\UE_5.8\Engine\Build\BatchFiles\Build.bat" CheeseStrikeEditor Win64 Development -Project="<repo>\CheeseStrike.uproject" -WaitMutex`. Close the editor first, or build from inside it with Live Coding: a running editor holds the module's DLL.
- **Assets are in a private submodule.** This repository is public; `Content/` is the private `cheesestrike-assets` repository, because most assets may not be redistributed (Epic's template content under the Unreal Engine EULA, Fab content under its licences). Never commit an asset to this repository. A change to assets is a commit in `Content/` (on its `main`, pushed first), then a commit here that moves the submodule to it, in the same pull request as any code it goes with. Add a row to `Content/LICENSES.md` for every pack or file brought in, with its source and licence, and keep the folder each pack came in (`Content/<Pack>/`); in the same change give it a line in the game's credits (`Source/CheeseStrike/UI/CheeseStrikeCredits.cpp`, the front end's Credits page), naming it as its licence asks: a Creative Commons Attribution work by its title, author and licence (`CheeseStrike.Project.TheCreditsNameEveryone` checks every linked title in such a row). A new clone needs `git submodule update --init`, then `git lfs pull` inside `Content/`. Without the submodule the code still builds, but the project has nothing to open and the tests that check content fail.
- **Git LFS.** Binary files go through Git LFS in both repositories (`.gitattributes`). Run `git lfs install` once on a new machine. Don't commit `Binaries/`, `Intermediate/`, `Saved/` or the Visual Studio files; `.gitignore` leaves them out.
- **Scale.** The world is life size: Unreal centimetres and a 180 cm player. The Godot game was three times life size; [docs/unreal/design.md](docs/unreal/design.md#scale) says how its numbers convert.

# CheeseStrike: Gouda Overload

A multiplayer first-person shooter for Steam, made with Unreal Engine 5.8 in C++. The cover is cheese, and a minute into every match giant mice come and eat it. [docs/unreal/design.md](docs/unreal/design.md) is the whole game as a specification, and [docs/unreal/spike.md](docs/unreal/spike.md) is the plan the project is being built by. The game was first made in Godot; that version is kept at the `godot-final` tag, and its code there is the reference wherever the design document is not enough.

The project is at the repository's root: `CheeseStrike.uproject`, `Source/CheeseStrike/` (one game module), `Config/`, and `Content/`, which is the private `cheesestrike-assets` repository as a git submodule (see below). It began as Unreal's First Person template with its Shooter variant; `Config/DefaultEngine.ini` redirects the template's script package and classes to ours, and fixes two mistakes in the template's own content. The template's shooter level is the playground until the game has arenas of its own; its game mode override is cleared, so it plays with the game's own character, and its weapons, pickups and enemies are the template's and don't yet work with it.

## What the port keeps

The Godot game is the source of the design, not a thing to copy. Keep what Unreal and its First Person template do well (their input, movement feel, camera, scale and conventions) and port the game's ideas and tuning where they matter: the cheese that is cover and gets eaten by the mice that come partway through a match, so that a map opens up and the fight intensifies; the weapons' roles and roughly their numbers; the modes; the Overload. Don't port the Godot key bindings, speeds, scale or maps for their own sake. Words: a player is killed and scores kills, never knocked out. The Godot maps were placeholders; a placeholder map (the template's shooter level) does until there is a plan for how levels work.

## Testing rules

Every change follows both of these, in the same pull request as the change:

1. **Automated tests.** Assess whether the change's behavior can be covered by an automated test. If it can, write the test with the change. Tests are Unreal Automation tests in `Source/CheeseStrike/Tests/`, named `CheeseStrike.<Area>.<What it checks>`. Rules belong in plain C++ that a test can call without a world, as the Godot game kept its rules in plain classes. What needs the game running gets a test that plays it in the editor (`CheeseStrike.Play.*`, through `Tests/PlayTesting.h`): alone, or as a host with joiners in the same process for anything networked, each player driven by a play script (the same commands as `tools/play.ps1` uses) and the result read off the characters and the match state. Such a test takes ten to twenty seconds, so put several checks in one.
2. **Manual tests.** Assess whether `docs/manual-tests.md` needs rows added, changed or removed. Behavior that an automated test can't cover gets a row. A row that becomes covered by an automated test is deleted.

Say what you concluded in the pull request description, including when the answer is that no test or no manual-test change was needed.

Before pushing, run the tests: `python tools/run_tests.py`, which builds the editor and runs every `CheeseStrike` test headless, or `python tools/run_tests.py CheeseStrike.<Area>` for some of them. It fails if no test ran.

To see a change in the game itself, play it without a person: `powershell -ExecutionPolicy Bypass -File tools/play.ps1 -Script tools/play/<script>.txt -Tag <name>` starts the game rendering offscreen (no window, and the person at the PC keeps their mouse and keyboard; the editor must be closed), plays the script's commands through injected input (`Source/CheeseStrike/Dev/CheeseStrikePlayScript.h` lists them: hold and release actions, look, screenshot, state, a console command such as `CheeseStrikeDie`, quit), saves screenshots to `Saved/Screenshots/WindowsEditor/`, and traces the character's state ten times a second into `Saved/Logs/<name>.log` (`-TraceState`). `-ClientScript` starts a second game that joins the first, for two players, named by `-Name` and `-ClientName`; `-Extra "?listen?KillLimit=1"` passes the host's options. Read the numbers first (speed, eye height, crouched, health, ammunition, shots and hits), then the pictures. Write a script for what a change needs (the ones in `tools/play/` are examples), and give it `-StartAt X,Y,Z,Yaw` for a spot with room. The template's first-person rifle sits large and low in the view, so a thing on the floor ahead is often behind it: look to the side to see it.

## Working in this repo

- **Pull requests only.** `main` is protected: changes arrive through a pull request, merged by rebase. Keep each commit on a branch meaningful, since every one lands on `main`.
- **After merging, move on.** Once a pull request's checks have passed on an up-to-date branch, merge it and carry on.
- **Delete the local branch after merging.** A rebase merge rewrites the commits, so git won't see the branch as merged and `git branch -D` is needed. Return to an up-to-date `main`.
- **No AI attribution.** Don't add "Generated with Claude Code" to pull request descriptions or a `Co-Authored-By` trailer for Claude to commits.
- **C++ first.** Gameplay is written in C++ so that it can be read, edited and reviewed as text. Blueprints are for wiring assets to C++ classes (meshes, sounds, animation, the values a designer tunes), not for logic. A Blueprint can't be read in a diff, so say in the pull request what changed in one. Input actions and key bindings are made in code too (`Source/CheeseStrike/Input/`), not kept as assets. Assets the C++ needs (meshes, animation Blueprints) are found by path in constructors.
- **The menus are Slate in code.** `SCheeseStrikeMenu` (`Source/CheeseStrike/UI/CheeseStrikeMenu.h`) draws the front end, the matches found, the lobby (where the host sets the rules, and everyone sees who is in), the pause menu (the host's with Back to Lobby, below) and the settings, with its icons and the lobby's tile from `Content/UI/` (a cut face of Swiss cheese, its holes apart, made by `tools/art/menu_tile.py`); which page shows follows the match's state (`CheeseStrikeMenu::PageFor`, run each tick by the player controller), not clicks. While a page shows, only the menu takes input: the character ignores its player's (`ACheeseStrikeCharacter::TakesInput`), so a paused player can't move or fire, the settings opened from the pause menu included; the game goes on behind them (alone too), blurred and darkened by an `SBackgroundBlur` (`CheeseStrikeMenu::PauseBlur`, `IsBlurringTheGame`). Each page is drawn again only when something on it changes (`LobbyKey`, `PageKey`, checked every frame), so that its spinner turns on unbroken and a slider being dragged stays; the seconds count down by themselves, and the lobby's rules show their values as they are (`MakeDropdown`'s `GetChosen`, `MakeMapPicture`), so that a rule changed draws nothing afresh on the host's machine or a joiner's (`GetLobbyBuilds`; a lobby drawn afresh flickers): only the mode, the seats and the status do. Nothing in the lobby wraps its text at the width it last had (`AutoWrapText`, which for a page drawn afresh is none for a frame, and would shrink the whole lobby to fit for that frame): it wraps at a width given (`WrapTextAt`) or not at all. The lobby's rules are rows of dropdowns (`MakeDropdown`, an `SMenuAnchor` in the current window, styled as the menu; a joiner sees the host's choices in plain boxes, `MakeReadOnly`), so that the whole lobby fits a 16:9 screen with no scrolling (`CheeseStrike.Play.EveryoneEntersTheMatchTogether` measures it at 1280x720, the smallest the game's window may be made, `CheeseStrikeMenu::MinWindowWidth`, and at 1600x900, 1920x1080 and 2560x1080; in a squarer window, which has less room across, the lobby is drawn smaller to fit rather than clipped, `ShrinkToFit`); while the host has one open the lobby isn't drawn again (`CheeseStrikeMenu::ShouldRedrawLobby`), unless its status changes, and `CheeseStrikeDropdown <n>` opens one for screenshots (`tools/play/ui_polish_server.txt`). Hosting and joining show a spinner and take no more clicks until the level they lead to has loaded or they fail (`UCheeseStrikeSessionSubsystem::GetPending`); while any level loads, which stops the game's thread for seconds, the engine's loading screen draws the cover (below) on a thread of its own, its spinner turning (`UCheeseStrikeCurtainSubsystem::OnLevelLoading`, the game only: the editor has none). The lobby's columns are the sides, eight seats each: the players in the order they joined (`ACheeseStrikePlayerState::GetJoinOrder`), the bots that will stand in in the order they were added, then open seats (`CheeseStrikeRules::Seats`, `WithEmptySeats`), each a chip in its side's colour (`CheeseStrikeMenu::TeamColour`), the player's own edged in cheese and a long name (Steam's 32 letters) written smaller (`SeatNameSize`) and cut with an ellipsis; `MakeSeatColumns(bTeams)` draws them, or for a free-for-all every seat in that order in two columns. In a mode of sides a player goes over to the other side with its Join button or a click on a seat there (`ACheeseStrikeGameMode::SwitchSide`, if it has fewer than eight players: a bot makes way), and the host moves a bot by clicking it (`MoveBot`: every bot then keeps its side, `?BotSides=` carrying them to the match's levels); the host keeps each player's side and place in the order across the match's levels (`UCheeseStrikeSeatMemory`, since every travel has everyone join afresh). Once the countdown has begun nothing in the lobby can be changed (`CanChangeLobby`: the host's rules show as a joiner's), and a match can't be started with fewer than two in it, or a side empty: Start the Match is faded and says why (`CheeseStrikeRules::WhyNotStart`; the console's `CheeseStrikeStart now` skips the check). The host's Leave reads Close Lobby, and in a match the host's pause menu has Back to Lobby in place of Leave the Match (`ACheeseStrikePlayerController::CanGoBackToLobby`): asked to confirm (`SCheeseStrikeMenu::ConfirmBackToLobby`), it ends the match with no results or podium and takes everyone, joiners and bots, back to the lobby with the rules and sides as they were (`ACheeseStrikeGameMode::BackToLobbyMidMatch`, `CheeseStrikeBackToLobby` on the console; `CheeseStrike.Play.TheHostTakesEveryoneBackToTheLobby`). Closing the lobby: leaving, or quitting the game, the host tells every joiner first (`UCheeseStrikeSessionSubsystem::SayGoodbye`, `ClientHostLeft`), and a joiner put out of a match, by the host or a lost connection, is back on the front end with a note saying why until they press OK (`GetFarewell`, `CheeseStrikeSessions::EFarewell`). The front end and the lobby have music (`UCheeseStrikeMusicSubsystem`: the songs of Fab's "FREE Cyber Metal Music Pack", one after another at random, never the same twice running, `CheeseStrikeMusic::NextSong`, at the settings' music volume, `MusicSoundClass`), going on from one level to the next and fading out over the countdown into the match (`CheeseStrikeMusic::IsWanted`). In a session everyone hears the host's song at the host's point in it: the host's machine picks the songs and puts the one playing and the server's time it began on the game state (`GetMusicSong`, `GetMusicStartedAt`, written afresh on each level's, `CheeseStrikeMusic::HandOver`), and a joiner's plays that song from there (`UCheeseStrikeMusicSubsystem::Follow`, `OffsetFor`), switching when the host does and put back in step when more than a quarter of a second out (`ShouldFollow`; `CheeseStrike.Play.EveryoneInTheLobbyHearsTheSameSong`); the front end alone picks its own. What the lobby's bottom says is `CheeseStrikeMenu::LobbyStatus`: a joiner's lobby says "Joining the lobby" until the host's match has come with the host and the joiner in it, and a joiner the server tells to travel shows where to at once (`PreClientTravel`), and goes on showing it (not the front end) once the connection to the level being left has closed. A player is in a match only in a level with a connection of its own: while joining, the engine calls the level left behind a client. Each second of the countdown sounds a soft tone and its end a brighter chime, on every player's machine (`CheeseStrikeTones`, made in code, `SoundCountdown`). After every level load a cover in the lobby's looks, saying where to (`WhereTo`: the lobby, back to the lobby, or the map), stays up until the view is ready (`UCheeseStrikeCurtainSubsystem`, `IsViewReady`): a joiner otherwise sees the engine's view from the world's origin before their controller and character come. While the match travels to the map the host picked, the lobby shows, saying where to; back to the lobby after the results and the podium (below), the last frame the view drew stays on the screen (`UCheeseStrikePostGameSubsystem::HoldWhatIsShown`, over everything: read as the engine's screenshots are, after the frame is drawn and before it is shown, so at the view's own resolution and quality in a window, full screen or offscreen, with the HUD's words and no Slate; a spinner in the corner only for a wait past a moment) until the player's lobby is there and ready (`ACheeseStrikePlayerController::IsLobbyReady`), never a lobby still being made, and then fades away over it. Travel URLs are the map and the options only (a URL naming the port is refused), and a travel keeps any option of the last URL the new one doesn't name (a joiner following the server drops the host's `?Nick=` from the server's URL, keeping their own: `ClientTravelInternal`), so the rules' options always carry every value (`?Bots=-1`, `?Players=0`). Hosting goes straight into the lobby with the usual rules (`CheeseStrikeRules::HostOptions`: Gruyère Grotto, Deathmatch to 50, back 5 s after a death, seven bots of normal skill), the modes listed teams first and free-for-all last (`CheeseStrikeModes::LobbyOrder`); the host picks the map there (`CheeseStrikeRules::Maps`), and when the match starts everyone travels to it (`?Players=`) and it begins when every player's machine has said its level is loaded and its view can be shown (`ServerReady`, `CheeseStrikeRules::ShouldBegin`), or after `WaitForPlayers` seconds for anyone who never comes: until then everyone, the host too, stays behind the cover, which says how many are ready, and the bots come in as it begins. A match waits in the lobby (`AGameMode`'s delayed start) until the host starts it, with the design's five-second countdown, and `RestartGame` brings everyone back to the lobby after the results and the podium (`CheeseStrikeRules::ResultsTime`). `?StartNow` on the URL skips the lobby: `tools/play.ps1` and the play tests use it unless told to use the lobby (`-Lobby`, `FSession::bLobby`), and once in, the match counts in before it begins (see below).
- **A podium ends a match.** Three seconds after the results (`CheeseStrikePodiums::After`) every machine puts up the podium for fifteen (`Seconds`), counted down to the lobby: `ACheeseStrikePodium` (`UI/CheeseStrikePodium.*`), a stage of its own made on each machine for its own player (`ACheeseStrikePlayerController::UpdatePodium`, never replicated), high over the level (`StageAt`) in a closed cheese cellar of its own with its own lights, camera and exposure, the top three on pedestals of stacked cheese wheels (the first in the middle and highest, the second on the left, the third on the right), each their own hero in their side's colours (`ACheeseStrikeCharacter::BodyOf`, as their character has it) playing one of its own Paragon emotes, a victory pose, a boast and a taunt by place (`CheeseStrikePodiums::Emote`; each a movement, never a held pose, which the play test checks by its bones moving for every hero on every place), with its own gun. Who stands on it is `Rules/CheeseStrikePodiums.h` (tested in `CheeseStrike.Podium.*`), ordered as the scoreboard orders them (`RankedStanding`: the kills; Gun Game's step first; the solo hill's points first), and in a mode of sides the winning side's best only; fewer places with fewer players. The HUD draws nothing else over it but its words (`UI/CheeseStrikePodiumHUD`: who won, each place in the countdown's cheese lettering with the name and score on a plate under it, the countdown, which fades out in its last second); the host has a Slate button to go back sooner (`SCheeseStrikePodiumSkip`: a click, Enter or A; `ACheeseStrikeGameMode::BackToLobbyNow`, `CheeseStrikeSkipPodium`). Its last frame is what the post-game screen holds until the lobby is ready. `CheeseStrikeEndMatch` on the host's console ends a match for looking at it (`tools/play/podium.txt`, `podium_skip.txt`), and `CheeseStrikePodiumBodies <first> <second> <third>` puts any heroes on this machine's places (`tools/play/podium_heroes.txt`); `CheeseStrike.Play.ThePodiumShowsTheTopThreeAndGoesBackToTheLobby` plays it with a joiner and a bot. Bots have player ids of their own (`ACheeseStrikeBotController::InitPlayerState`), so that they wear every hero in turn as players do.
- **A gamepad plays it all.** Every action has a gamepad button beside its keys (`Source/CheeseStrike/Input/`, tested in `CheeseStrike.Input.EveryActionHasAGamepadButton`), laid out as Call of Duty's defaults with the d-pad for the weapons and the streak: left stick moves and, pressed, sprints until it is let go (`SprintToggle`), right stick looks and, pressed, draws the knife; A jumps, B crouches or stands (`CrouchToggle`; slides at a sprint), X reloads, Y the next weapon; LT aims, RT fires; LB interacts, RB throws a grenade; the d-pad draws the primary (up), the sidearm (left) and the knife (right), and calls in a streak (down; Q on the keyboard); View the scoreboard, Menu pauses. The look stick turns on a curve (`CheeseStrikeInput::StickTurn`: past the dead zone squared, faster held at the edge) and gets a light aim assist that the mouse and the bots never do (`Input/CheeseStrikeAimAssist`: slower over an enemy in sight, a small pull while turning; tuned by `CheeseStrike.AimAssist.*`, turned off in the settings). What a player last played with is watched in everything Slate gets (`UCheeseStrikeInputSubsystem::GetDevice`, per Slate user), and a prompt that names a key asks for the device's (`UCheeseStrikeInputSet::Prompt(Player, &UCheeseStrikeInputSet::Interact)`): "HOLD E" or "HOLD LB", the weapons' 1, 2, 3 or the d-pad's arrows. The menus take the pad and the keyboard: each item is registered as it is made (`SCheeseStrikeMenu::Focusable`), the focus starts on a page's first item and comes back to the same one when the page is drawn again (`CheeseStrikeMenu::FocusAfterRedraw`), moves to the nearest item the way pressed (`CheeseStrikeMenu::NextInDirection`, the menu's own rather than Slate's, which doesn't look into a scrolling list), and is ringed in cheese unless the mouse is in use; A presses, a slider steps with left and right, a dropdown opens with its chosen item focused, and B or Escape shut a dropdown or go back. The space bar presses nothing in the menus, which Slate would take for Enter (`SCheeseStrikeMenu::OnPreviewKeyDown`): only Enter, a click or A. Every action's keys and buttons, the keyboard's and mouse's, an Xbox pad's and a Nintendo pad's, are on the settings' first tab, Controls (`EOptionsTab::Controls`, from the front end and the pause menu), a table read from the bindings themselves (`CheeseStrikeControls::Rows`), so that it stays right, and a new action gets a row of its own. A play script presses real keys through Slate with `key <name>` (the menus and the prompts see them; `tools/play/gamepad_menu.txt`) and says which device the player uses with `device gamepad`.
- **A match counts in, and a fresh spawn is a ghost.** When a match begins (everyone in, the covers lifted) and at each later round of a mode played in rounds, everyone comes in held where they stand while a count runs (`CheeseStrikeStart` in `Rules/CheeseStrikeStart.h`, tested in `CheeseStrike.Rules.TheMatchCountsInAndProtectionEndsOnAttackOrTime`): three seconds before a match, two before a later round, `?Countdown=` for another length or 0 for none (the play tests and `tools/play.ps1` use 0 unless they ask, `-Countdown` and `FSession::Options`). The game mode sets when it ends on the game state (`GetGoAt`, replicated, `IsFrozen`), before the characters come in; until then `ACheeseStrikeCharacter::CanAct` is false, so nobody moves, fires, changes weapons or calls in a streak (bots stand still too), but everyone can look round. The round's clock and the mice's arrival are counted from its end. The HUD draws it big in the middle (`UI/CheeseStrikeHUDCountdown.cpp`: 3, 2, 1 under GET READY, then FIGHT), and the player controller sounds the lobby's tones for it (`SoundCountdown`). A fresh character is protected (`IsProtected`: unhurt, and bots don't aim at it) for `CheeseStrikeRules::SpawnProtection` seconds from the end of any count still running, or until it attacks: a shot, a knife stroke or calling in a streak (`EndProtection`, on the server; the replicated `ProtectedUntil` takes it to every machine). While protected it looks ghostly on every machine, its body, its own first-person arms and its weapons wearing `M_Ghost` (`Content/CheeseStrike/Effects`, made by `tools/art/ghost_material.py`: unlit, translucent, a pale blue-white wash with a brighter rim and rising bands) as an overlay material (`UpdateGhost`; the first-person arms and weapon with a softer rim), fading out over half a second as the protection ends. `CheeseStrikeProtect <seconds>` protects the player's character for looking at it (`tools/play/ghost.txt`, `ghost_server.txt` and `ghost_client.txt`).
- **The settings are the engine's, made the game's.** `UCheeseStrikeSettings` (`Source/CheeseStrike/Settings/`) is the engine's `UGameUserSettings` (`Config/DefaultEngine.ini` names it), kept in `GameUserSettings.ini`: the graphics (quality preset, window, resolution, VSync, frame rate limit, as the engine applies them; not the window in the editor; full screen, the window is the screen's own and the resolution picked is what the game is drawn at, `ScreenPercentageFor`, since DirectX 12 has no fullscreen of another size), and the game's own, each applied as it is set: the look's sensitivity (the mouse's and the stick's), its share while aiming and inverting it, the gamepad's aim assist (`ACheeseStrikePlayerController::LookScale`, used by the character's `DoAim`; a play script looks as the usual settings would), the field of view from the top of the view to the bottom, 75 by default as in the design (the camera manager turns it into the engine's across, for the screen's shape), and the master and effects volumes (`ApplySound`: the audio device's volume, and a sound mix over every sound class but the menu's, run again after each level loads). The settings page has a tab for each kind (`EOptionsTab`: the controls' table, aiming, view, sound, graphics). Their rules (ranges, the field of view across, the resolutions offered) are `CheeseStrikeSettings::*`, tested in `CheeseStrike.Rules.TheOptionsOpenAndKeepToTheirRanges`.
- **Matches go through Steam.** `Config/DefaultEngine.ini` puts the game on the Steam online service (test app id 480) with the Steam net driver; a match is a lobby that `UCheeseStrikeSessionSubsystem` offers, finds, joins and leaves (`Source/CheeseStrike/Sessions/`), driven for now by the console commands `CheeseStrikeHost [?KillLimit=..]`, `CheeseStrikeFind`, `CheeseStrikeJoin <n>` and `CheeseStrikeLeave`. Steam is only used by `-game` and packaged builds with the Steam client running; the editor, the tests and `tools/play.ps1` (unless given `-Steam`) use the Null service, which does the same over the local network, so the flow is tested in the editor and Steam itself is checked by hand on two PCs with two accounts. A second game on the same PC and account never gets the first's lobby data from Steam.
- **The HUD is drawn in code.** `ACheeseStrikeHUD` (`Source/CheeseStrike/UI/`) draws everything over the view on the canvas, in the engine's bold condensed Roboto through a runtime `UFont`, its shapes made of triangles (`CheeseStrikeHUDDraw`; the canvas has no rounded shapes, so a box with rounded corners is a polygon, `CheeseStrikeHUD::RoundedRect`, with as many steps to its arcs as their size needs, `CornerSteps`, and a picture in one, a Steam avatar, a fan of textured triangles, `RoundedPicture`; a shape standing alone, its corners, discs and rings, has a soft edge a pixel wide that fades it out where its outline crosses a pixel, so that curves are smooth rather than stepped, `SoftEdge`, `OutwardMiters`, `FShapes::SmoothPolygon`, while pieces that meet edge to edge, the minimap's, stay hard but where cut to its rounded corners), by rules that are plain functions tested without a world (`CheeseStrikeHUDRules.h`, `CheeseStrike.HUD.*`); it draws nothing under the front end and the lobby. The minimap is made from the level itself (`FCheeseStrikeMinimap`: every visible static mesh that blocks players, outlined from above by its collision shapes and shown by its height against the player's, and the cheese as it is now), so a new map needs nothing for it (its doors drawn as they are, open or shut), its corners rounded (pieces cut to them, `ClipToConvex`), the player a wedge of cheese pointing the way they face; north is +Y on every map, and the name of the place the player is in (`ACheeseStrikePlace::NameAt`) shows under it, as the place a body fell does in the kill feed. A hit reaches the hurt player's machine through `ACheeseStrikeCharacter::ClientHurtFrom`. Over an enemy down in Execution whom a shot from where the player stands would not hurt, the crosshair is a cancel sign (`CheeseStrikeHUD::CrosshairFor`, by the mode's `LastStandHit`). The death screen shows for every death, out of the round too for a few seconds before the mode's notice (`ShowsDeathScreen`). A kill earns badges (`Rules/CheeseStrikeBadges.h`, `BadgesFor`, tested in `CheeseStrike.Badges.*`): HEADSHOT, ASSASSINATION (the knife from behind), EXECUTION, POINT BLANK (the shotgun within 2 m), LONGSHOT (40 m or more), REVENGE (on whoever last killed you) and ONE SHOT (full health to dead in one hit, not the Roquefort's headshot), worked out by the game mode from what the weapon told the victim of the fatal hit (`ACheeseStrikeCharacter::NoteHit`, `GetDeathFacts`) and who last killed whom (`ACheeseStrikePlayerState::GetLastKilledBy`), carried with the kill feed's entry (`FKillFeedEntry::Badges`), counted on the killer's player state (`GetBadgeCount`, for the achievements), and drawn as small cheese-gold pills (`CheeseStrikeHUDDraw::BadgePills`) before the killer's name in the feed, over the killer's popping kill count, and under the death screen's "BY" line. The start countdown's words are pictures of 3D cheese rendered in Blender (`tools/art/countdown_glyphs.py`, imported by `tools/art/import_countdown.py` into `/Game/CheeseStrike/UI/Countdown`, loaded by path). Who is on whose side is the mode's (`ACheeseStrikeHUD::AreTeammates` asks `ACheeseStrikeGameState::AreTeammates`), the minimap shows each enemy where they were last known to be, never in real time and never for merely being in sight: firing (`NoteShot`) or swept by the side's Unmanned Aerial Cheese (`IsRevealedTo`, or `RevealEnemies` on this machine), moved at most once a second (`CheeseStrikeHUD::FEnemyMarks`), health is a cross and a row of blocks, never a number, anywhere (`HealthFills`, red and breathing when low with the red edges, what a hit took lingering a moment), the score at the bottom is `ScoreSummary` (a free-for-all's or the sides' and the round), in rounded tiles whose words never run into the score (`FitScoreBlock`: a side's name has the score made smaller for it first, then is cut with dots), the run of kills is the kill-streak panel over the health (`UI/CheeseStrikeHUDStreak.cpp`: the count, popping at each kill, and a track to the streaks, `StreakPips`, `StreakNext`, `StreakPop`; `CheeseStrike.HUD.Streak` and `CheeseStrike.HUD.Score` show any for judging, `tools/play/hud_rounded.txt`), the list over the ammunition is `WeaponSlots` (the inventory's), and a player out of the round (`ACheeseStrikePlayerState::IsOut`) is struck through in the row, each tile framed in its side's colour (faded while dead, fainter out), with nothing under it, and a player down in Execution washed and framed in red-orange, "DOWN" across the tile's foot (`CheeseStrikeHUD::EStatus::Down`), and on the scoreboard (`DrawScoreboard`, `UI/CheeseStrikeHUDScoreboard.cpp`; - **Animation is composed in code.** `UCheeseStrikeAnimInstance` (`Source/CheeseStrike/Animation/`) builds the body's pose from the engine's standalone animation nodes (sequence and blend-space players, blends, mesh-space additives for the aim offsets, a slot for firing and reloading) and reads what the character is doing each frame; no animation Blueprint, so every machine's copy of a character animates alike and a new rig is a change of asset paths. Only nodes without folded properties are safe this way (the `_Standalone` players, `FAnimNode_TwoWayBlend`, `FAnimNode_MultiWayBlend`, `FAnimNode_ApplyMeshSpaceAdditive`, `FAnimNode_Slot`); the ordinary blend-space player, aim-offset and blend-by-bool nodes read Blueprint-only data and would fail in a packaged game. The rifle and its sounds are Lyra's (`Content/Characters/Heroes/`, `Content/Weapons/Rifle/`, `Content/Audio/`; `Content/LICENSES.md`), copied from the Lyra sample with their dependencies; the rifle is modelled along its Y axis and is turned a quarter turn in the hand bone `weapon_r`. The body, which others see and whose arms its own player sees (the first-person body is the same mesh and animation, its head hidden from its player and the camera just under its eyes, `FitFirstPersonBody`), is a Paragon hero: `CheeseStrikeBodies` (`Source/CheeseStrike/Animation/`) is the table of them (Lt. Belica, Murdock, Twinblast and Wraith, `Content/Paragon*/`) and says which a player has. In a mode with sides, each side has two heroes whose palettes go together, the Gouda Guys Murdock and Twinblast, the Mozza Radicals Belica and Wraith, worn by the players of a side in turn (by player id) and dressed in the side's colour, as the lobby and the HUD show it (`CheeseStrikeMenu::TeamColour`), on their armour (material instances in each hero's `Materials/Teams/`, made by `tools/art/team_looks.py`); in a free-for-all each player has one of the four in turn, in its own colours. The character puts on its player's every frame it lacks it (`UpdateBody`, from the replicated sides and ids, so every machine agrees; a fallen body keeps the one it fell in), and `CheeseStrikeBody <n> <side>` shows any of them, for looking (`tools/play/bodies.txt`). A hero comes from the Lyra project, where the user adds Paragon packs through the Epic Games Launcher: `tools/art/lyra_hero.py` (run there, holding the Lyra lock) retargets Lyra's rifle set to it through Lyra's UE4-mannequin IK rig, which fits every Paragon hero's bones, with the pistol, shotgun, melee and draw animations the other weapons are held by (`weapons` does only those, through the retargeter already made), and lists what it needs; `tools/art/copy_from_lyra.py` copies that in; `tools/art/fit_hero.py` (`animations` for the animations alone) strips Lyra's animation modifiers, cuts the textures to 1024 and drops the retargeted animations' tracks for bones the reference pose scales (Belica's face hangs from `faceAttach` at 0.79, and at 1 her eyes and lips swell; the animation also keeps those bones at that scale). One animation class plays them all (`UCheeseStrikeHeroAnimInstance`, which plays its mesh's skeleton's sets, the one for how the weapon in hand is held). The heroes' `weapon_r`, where they have one, stays where their own guns were, so the rifle rides `hand_r` at each hero's grip (`ACheeseStrikeWeapon::PutInHand`, turned as the mannequin's `weapon_r` holds it in the same frame of the idle, `tools/art/measure_bodies.py`), and their own guns are hidden (their material slots, or Belica's gun bones; and Murdock's metal brace round his right hand, which read as part of a gun, its bone `bot_hand`: `BuiltInWeaponBones`). Murdock's first-person body also hides his chest and helmet, which come before his eyes as he aims. To look at the body with one game, `CheeseStrikeOutside <distance> <yaw>` puts the view outside it (`tools/play/body.txt`); with two, the joiner starts 4 m from the host, facing it. The left hand is held on the weapon by `FCheeseStrikeGripIK` rather than by the animations' `ik_hand` bones, which the aim offsets leave behind: turned as the set's idle has it relative to the right hand (measured from that animation's first frame for each set and mesh, whatever the body is doing as the weapon changes), the middle of its closed fingers on the point the weapon's look names (`FWeaponLook::LeftHand`, on the fore-end, or round the hand on a pistol's grip; none leaves the hand free, as the knife does), since the heroes' retargeted animations put the free hand anywhere from the fore-end to past the muzzle; the arm stretches a little (`CheeseStrikeGrip::MostStretch`) rather than let go. Over the animations, in component space, `Animation/CheeseStrikeArmsPose` poses in code a slide (`FCheeseStrikeSlidePose`: crouched faster than a crouched walk, as any machine can tell, `CheeseStrikeArms::LooksSliding`; the hips dropped and laid back, the right leg out ahead along the floor, the left folded with its knee up, the gun kept up), the knife (`FCheeseStrikeKnifeHold`: the fist closed round it, the index finger curled as the middle one is; on the body others see, on guard ahead of the chest and swiped from the right shoulder down across to the left, `CheeseStrikeArms::KnifeSwipe`, from the weapon's `SwipePhase`), and its own player's arms in view (`FCheeseStrikeViewHold`, below). Firing and reloading play from the spine up (`FAnimNode_LayeredBoneBlend`), the legs walking on; the locomotion pose that feeds both is evaluated twice but updated once (`FCheeseStrikeSharedPose`), since a native graph has no cached poses. A player down in Execution's last stand lies on their back, posed last, in component space, by `FCheeseStrikeDownedPose` (`Animation/CheeseStrikeDownedPose.*`), from the crouched pistol set and by the mannequin's bone names every hero has (`CheeseStrikeDowned::PoseBones`, checked in `CheeseStrike.Animation.EveryBodyIsComplete`): the chest squared to the hips, the pelvis laid back on the floor where `CheeseStrikeDowned`'s rules (`Rules/CheeseStrikeDowned.h`) have the hips, the spine curled up and the torso turned about the hips until the left shoulder is an upper arm over the floor (propped on that elbow, by two-bone IK), the chest turned toward an aim to the side, the head looking along the aim, the pistol hand out along it from the right shoulder (for the first-person body, from the eyes, so that the arm never crosses the view), the legs out ahead along the floor by two-bone IK as far as there is room (`ACheeseStrikeCharacter::MeasureLegRoom`, a sweep ahead of the hips; bent up against a wall), pushing in turn as the body scoots or turns round, and a laboured breath; it is blended in over `CheeseStrikeDowned::Seconds` and out over `RiseSeconds`, bone by bone in local space, so going down and getting up don't snap. The first-person body plays it too, so the view (on its head, a little ahead of the face) sits low, about 40 cm up, looking past its own legs, drawn at the world's field of view while down so that the legs lie on the floor in view, the arm it is propped on hidden; the arms are left where the pose has them (no hip hold, no aiming down the sights). Its own player's weapon is placed in view by the right arm alone (two-bone IK, `FCheeseStrikeViewHold`; a grenade in the right hand, held and thrown, by `FCheeseStrikeGrenadeHold` after it), never by moving the body, so nothing of the body (Murdock's armour, a sprint's lean) is pushed before the eyes, and the camera stays on the head just under the eyes (`PlaceView`): down the sights so that the weapon's sight line runs down the view through the eye (the look's `Sight`, or the rifle's from its bounds, `WeaponSight`), and at the hip that moved and turned in view as its hold has it (`CheeseStrikeWeaponLooks::HipFromAimed`), so that every gun sits alike low on the right whatever its shape; with the animations' bob and a montage's movement (firing, reloading) but neither their lasting lean nor their tremble (the animations' compression shakes each joint by a tenth of a degree or so, which a gun's length shows: the hand follows them steadily, `CheeseStrikeArms::SteadyRate`; `CheeseStrike.Play.TheWeaponIsSteadyInView` measures it with `ACheeseStrikeCharacter::TakeViewTremble`); coming up from below as it is drawn, carried across the body at a sprint and canted in a slide, when the view also leans into it (`GetViewRoll`, the camera manager's), the knife on guard low on the right and swiped across the view. The first-person body is drawn at a field of view of 76 (the world's is wider), which keeps a weapon this close from stretching. Shots leave from the eye along the view. Down, the view is kept out of the floor and of what it lies against (`KeepDownViewClear`: a ball swept from the capsule's middle, and 22 cm over whatever is under it). Each hero's ragdoll is `PA_<Hero>_Ragdoll`, made by `tools/art/ragdolls.py` (Paragon's own physics assets are rough bounds ones, which as ragdolls float): a body for each part that moves on its own and none under the head (so the face stays on) or for its own guns, every joint on hard limits as a person's (the script's table: hinged knees and elbows, a spine and neck that twist little), damped so that it settles, and the dying character's speed passed to the body; `CheeseStrike.Play.AKillIsScoredAndTheKilledComeBack` checks the body comes to rest within those limits on both machines. `tools/play/ragdoll.txt` watches a body die four ways (with `-FixedFps 30`, so that a busy PC doesn't show the fall in slow motion).
- **Maps are built by scripts.** A map is a Python script in `tools/art/` that builds its level from nothing in the editor (`build_creamery.py` for The Creamery, with `build_materials.py`, `cheese_material.py` and `wax_material.py` for its materials), so a map can be read and changed as text; its notes are in `docs/unreal/maps/`, and [docs/unreal/maps/principles.md](docs/unreal/maps/principles.md) is how to design and build one. The scripts are built from `tools/art/map_kit.py`: ground, walls, ramps, stairs, props, cheese in blocks, walls, floors and stacks, buildings of several storeys, tunnels, bridges, doors (`ACheeseStrikeDoor`, which open as anyone comes up to them), starts, the mice's ways in, named places (`ACheeseStrikePlace`), the navigation bounds and the light; `build_level` builds, checks and reports. `tools/art/map_picture.py` takes a map's picture for the lobby. Its art is free Fab content: Fab's web page downloads a listing's files (a Megascans surface's texture set, a model's FBX), kept outside the repository in `C:\Hamid\code\FabDownloads`, and `import_fab.py` imports what the maps use into `Content/Fab/` (box collision, Nanite, textures cut to 2K or 1K); a listing that only comes in Unreal's own format needs the Epic Games Launcher, which a script can't drive. Surfaces are drawn on the maps' blocks from world space (`M_Surface`); a model that stands for cover is scaled to fill its block. Every block of cheese is an `ACheeseStrikeCheese` (`Source/CheeseStrike/Map/`) naming the structure it belongs to, for the mice to eat. A script that saves a level must check the level it has open: the editor opens on the shooter level, and a failed open builds into that.
- **Weapons are numbers in code.** Every weapon is a plain `FWeaponStats` in `Weapons/CheeseStrikeArsenal.cpp` (the design's table, its lengths divided by three; tested in `CheeseStrike.Weapons.*`), with the lists the game is played by (the primaries, Gun Game's ladder). Every character carries a primary (the Colby Carbine, the weakest, unless its player chose another with `CheeseStrikeLoadout <weapon>`, which takes effect at the next life, or at once just after coming in; the play tests come in with the Cheddar Blaster they were written for, `CheeseStrike.SpawnPrimary` and `FSession::SpawnPrimary`), the Curd Pistol and the Cheese Knife (`UCheeseStrikeInventory`, a component of the character's), and two cheese grenades, a count of their own apart from the weapons' slots (`UCheeseStrikeGrenades`, by `Weapons/CheeseStrikeGrenadeRules.h`, tested in `CheeseStrike.Weapons.AGrenadeBurstsAndFallsOff` and `CheeseStrike.Play.AGrenadeIsThrownAndBursts`): G (RB) held puts the weapon down out of view and brings the grenade up in the right hand, the left let go, and back after the throw or a cancel (`CheeseStrikeGrenades::SwitchStep`, posed in code on both bodies by `FCheeseStrikeGrenadeHold`, the fingers closed round it in the palm, `UCheeseStrikeGrenades::InPalm`; others see it held through the replicated `bHoldShown`), and on the player's machine alone its arc, worked out as the grenade flies (`UCheeseStrikeGrenades::PredictPath`, which bots use too), as yellow dots in the world with a mark where it first comes down; let go, it is thrown overhand with the right hand (`CheeseStrikeGrenades::ThrowHand`, on every body), and changing weapons, reloading, going down or dying puts it away (`CheeseStrikeGrenades::HeldThrow`); the server lets it go a moment later where the right hand lets go of it (`ReleasePoint`, by the same numbers as the throw's pose, so that the arc shown is the one flown; `tools/play/grenade_switch.txt` looks at it), an `ACheeseStrikeGrenade` (a frag grenade of yellow holed cheese with a steel fuse, spoon and ring, `tools/art/weapon_models.py`, drawn in the HUD as one too, `UI/CheeseStrikeGrenadeHUD`) that flies in an arc, bounces off the world but not players, rolls to a stop and bursts after its fuse, harming whoever the burst can see within its radius by the match's rules for who may hurt whom (never a teammate), as the thrower's kill, and the thrower too (`TakeOwnBlast`: a death by one's own grenade is counted as a fall is, "blew themself up"); bots throw one now and then, mostly at an enemy just gone behind cover, along an arc worked out against the world, and run from one about to burst that can hurt them (`tools/play/grenade.txt` looks at one): the server spawns each as its own `ACheeseStrikeWeapon`, with its own rounds, and every machine shows only the one in hand. Changing (1, 2, 3, the wheel) happens at once on the player's machine and is asked of the server through the weapon being drawn, so that its shots arrive after it; a weapon fires only once its draw time is past, there and on the server. A mode changes what a character carries on the server (`Give`, `GiveOnly`, `RestrictTo`, `HoldNow`), in its `SetPlayerDefaults` or when it likes. The knife strikes rather than fires: a swipe across the aim (tried along it and then out to 45 degrees either side, a few degrees at a time, `SweepDirections`), 1.8 m long, decided on the server as shots are, deadly in the back; the striker stays where they are (no lunge), and both bodies swipe it (`FCheeseStrikeKnifeHold`, `FCheeseStrikeViewHold`). Players bleed molten cheese, for show on every machine that draws (`Effects/CheeseStrikeCheeseBlood`, by `Rules/CheeseStrikeBlood.h`, tested in `CheeseStrike.Blood.*`): read as a liquid, not balls: a hit's brief misty spray along the shot, a soft puff where it went in (and for a harder hit where it came out) and a score or two of fine drops gone in 0.4 s (`ACheeseStrikeCharacter::MulticastBleed`, sent with the hit), an execution's stab spurting and gushing a big fan of fine spray with puffs of mist over a spreading pool, and a stomp's fire-hydrant jet from where the head was (400 to 500 drops a second for two seconds at 8 to 12 m/s in a narrow cone, falling as they fly, each placed where it would be had it left at its own moment in the frame, so that the stream is unbroken), with a sheath of mist at its source and a spreading pool (`UCheeseStrikeLastStand::Bleed`); its drops one instanced mesh (a small teardrop, drawn out along its flight the faster it goes, `CheeseStrikeBlood::DropStretch`) flown by simple ballistics, its mist another (flat cards turned to the camera, each faded by its instance's custom data), and its splats and pools decals (characters receive none), all capped; its looks are made by `tools/art/cheese_blood.py` and loaded by path, and `CheeseStrikeBleed <damage> <yaw>` shows a hit's (`tools/play/cheese_blood.txt`). Shots are heard whole by the shooter and, by everyone else, from where they were fired, fading and growing duller with distance and only so many at once (`CheeseStrikeGunfire`; Lyra's sound waves carry no attenuation of their own); `CheeseStrike.TraceGunfire 1` logs each. The Dual Burratas are two guns, one in each hand (`FWeaponStats::bDual`), a shot a pull (at most ten a second), firing in turn (`CheeseStrikeWeapons::DualHand`), each flashing at its own muzzle: the second gun rides the left hand, held as the right holds the first mirrored across the body (`ACheeseStrikeWeapon::MirroredGrip`), and both bodies hold the hands apart, the left the mirror of the right (`FCheeseStrikeDualHold`, `Animation/CheeseStrikeDualHold.h`), with no sights to aim down. Each weapon's look is a row of `CheeseStrikeWeaponLooks` (`Weapons/CheeseStrikeWeaponLooks.cpp`): its model (Lyra's rifle, pistol and shotgun; Fab's PPSh-41, DP-28, SV-98, M4 and M1911, imported by `tools/art/import_weapons.py`; the Cheese Knife and the muzzle flash, made by `tools/art/weapon_models.py`) placed in the rifle's grip frame, its materials, sounds, sights, muzzle and where the left hand holds it. The weapon loads them by path as it becomes that weapon, so that the scripts can rebuild them, and their folders are in `DirectoriesToAlwaysCook`. The cheese is one material, `M_CheeseWeapon` (`tools/art/weapon_materials.py`), which turns the parts a mask names (a Fab gun's wood, masked by `tools/art/weapon_textures.py`; a Lyra gun's painted panels) or a box in the model's own space into mottled, holed, veined or waxed cheese, in that space so that it moves with the weapon; cheese lighter than the arena's reads as white plastic. The HUD's pictures of the weapons are side views drawn by `tools/art/weapon_icons.py`. Each way of holding (`ECheeseStrikeHold`: rifle, pistol, shotgun, knife) has its animations on every hero (`UCheeseStrikeAnimInstance::FindSets`; a hold a body has none for plays its rifle set). At the hip each weapon sits in its own player's view where it is aimed, moved down and to the right and turned a little by its hold (`CheeseStrikeWeaponLooks::HipFromAimed`; the knife at `KnifeHand`), however the body leans: Lyra's crouched and moving poses bring the weapon up towards the eyes, which would fill the view. `CheeseStrike.TraceView 1` logs where the weapon is in view every frame (2: and the arms' bones); `tools/play/sprint_slide.txt` and `knife_swipe.txt` look at the sprint, the slide and the knife's swipe. A scoped weapon, aimed, hides the arms for the HUD's scope. `CheeseStrikeArm <weapon>` puts any weapon in hand at once (not in shipping builds); `tools/play/weapon_looks.txt`, `weapon_heroes.txt` and `pistol_view.txt` look at them.
- **Weapons lie on stands.** Every map has four to eight weapon stands at fixed spots (`ACheeseStrikePickup`, `Weapons/CheeseStrikePickup.*`, placed by the maps' scripts with `kit.pickup`, which keeps the cheese under each so the mice never eat its floor), each a low plinth with a pad glowing in the one cheese gold every weapon has (`CheeseStrikePickups::WorthColour`; what a gun is worth, `Worth`, only decides where it lies and what bots want) and the weapon floating and turning over it (two guns both); the better at the riskier spots, both sides reaching them alike. The rules are `Rules/CheeseStrikePickups.h` (tested in `CheeseStrike.Pickups.*`): everyone comes in with the weak Colby Carbine; nothing is taken by walking over it: a press of Interact (E, LB) near it takes the stand's weapon, the HUD naming the swap (`UI/CheeseStrikePickupHUD`), and one's own weapon tops up its rounds (`UCheeseStrikeInventory::PressForPickup`, `TakePickup`, `SwapPrimary`, in hand at once); the primary carried drops to the floor with its rounds, the Carbine too, an `ACheeseStrikePickup` of its own (`Drop`, `IsDropped`: no plinth, lying on its side) that anyone takes with the same press, gone after 20 s (blinking at the end), at most 12 about (`CheeseStrikePickups::DroppedSeconds`, `MostDropped`), and cleared at a new round; `CheeseStrikeStand <weapon>` and `CheeseStrikeDropWeapon <weapon>` put one ahead for looking (`tools/play/pickup_looks.txt`). The server owns the stands: taken, one is empty for 60 s (the replicated `BackAt`; `CheeseStrike.PickupSeconds` for the tests), every machine showing its weapon as a ghost (`M_Ghost`) over a dim pad and the HUD the seconds over it; a new round puts every weapon back; Gun Game has none (hidden). The minimap shows them as diamonds. Bots go for a better weapon near them, on a stand or the floor, with nobody in sight, and press for it there (`ThinkAboutPickups`, `CheeseStrikePickups::BotWants`). `CheeseStrike.Play.AWeaponIsTakenFromItsStandAndComesBack`, `GunGameHasNoPickups` and `ABotGoesForABetterWeapon` play them, and `CheeseStrike.Play.AfterTheMice` checks every map's, the Proving Ground having none (`Tests/PickupChecks.h`: how many, fair, the better riskier, room and a way to each, clear of King of the Hill's spots, a floor after the mice).
- **Bots are played in code.** `ACheeseStrikeBotController` plays a bot on the server, by the rules in `Rules/CheeseStrikeBots.h` (the design's skill table, aim error that steadies as it tracks, turning no faster than its skill, bursts and rests, a sight cone, keeping to its weapon's range), tested without a world in `CheeseStrike.Bots.*`. It sees by line traces, walks the navigation mesh (`Config/DefaultEngine.ini` builds it when a level starts, in the level's `NavMeshBoundsVolume`, and rebuilds it where the level changes; a play test of the level the editor has open builds it afresh in `StartPlaying`, since playing copies the editor's, which may be unfinished), and works its character as a player does: path following and movement input, its control rotation for the view, the character's `Do*` actions for the trigger, the sights, reloading and changing weapons (the primary it took from a stand, the pistol when the magazine runs out with someone near, the knife up close: `CheeseStrikeBots::ChooseWeapon`); the weapon aims a bot's shots by its control rotation. In Execution a bot never fights someone down: it executes an enemy down in reach at once, goes to execute one further off (`ThinkAboutTheDown`, `CheeseStrikeBots::GoesToExecute`: even mid-fight, for one nearer than the enemy it fights), coming from outside their aim and swerving while in it (`CheeseStrikeBots::FinishApproach`), as widely as the floor either side allows (measured by a navigation raycast; straight on in a hallway, `SwerveWidth`), its goal kept on the navigation mesh and its path asked for at most every 0.3 s (`ShouldRepath`), and with no enemy in sight revives a teammate down by holding Interact; roaming, bots keep away from their teammates and where they are going (`CheeseStrikeBots::RoamScore`), so that a side spreads out; a bot that gets nowhere is stuck by where it is, not its velocity. No behaviour tree or blackboard assets. The host picks the skill in the lobby (`?BotSkill=`). Play tests get no bots unless they ask for them (`?Bots=` in `FSession::Options`); `tools/play.ps1 -Bots` fills a match with them.
- **The mice eat the cheese.** Three minutes into a match (`?MiceAt=` for sooner, `?Mice=0` for none) the game mode sends in one mouse for every 25 blocks of edible cheese, three to twenty-four, at the level's `MouseEntry` points (on top of its edge, facing in; a map without them or without cheese has none). `ACheeseStrikeMouse` (`Source/CheeseStrike/Map/`, by `Rules/CheeseStrikeMice.h`) runs on the server: it goes for the cheapest block (distance, plus four times its height, plus more for another mouse's, and more near the other mice and their blocks, so that they spread over the map: `CheeseStrikeMice::CrowdCost`), walks the navigation mesh to a spot beside it (never on top of it) with its own path following (finding its way afresh every few seconds, and when it has fallen) and keeps to the ground (falling when what it stood on is eaten), bites every half second, at a pace that has every map eaten bare about eight minutes after the mice come, steadily (`CheeseStrikeMice::Pace`: a bite is 100 times the cube of the share of the cheese left over the share a steady eating would have left by then, from 0.15 to four times, a block at a bite; the game mode gives each mouse the schedule, `SetSchedule`, and logs how they are getting on every ten seconds, `Mice: ... blocks left`), so `CheeseStrike.Play.AfterTheMice` plays every map's mice (at a fixed step, faster than real time) and checks all is eaten within a minute and a half, not most of it in the first 25 s, and the mice eating spread out, runs from shots that hurt it by 300 (and then eats away from there, on the far side of the map's middle if it can, for a minute or four blocks: `CheeseStrikeMice::ScareCost`), and gives up on a block it makes no progress on. It reaches 2.6 m across and 4 m up (rearing up to an upper storey's wall). Cheese it can't walk to it walks as near as it can to and leaps onto (`LeapTo`: across a gap, up to a floor no stairs reach, or onto a block standing alone, which it then eats from on top and falls with, `EatsUnderfoot`); and 40 s after they came (`CheeseStrikeMice::BoundAfter`) a mouse with nothing it can walk or leap to bounds straight to the nearest such cheese (`BoundTo`). One that has bitten nothing for 15 s comes in again at another way in. Once no edible cheese is left (`CheeseStrikeMice::ShouldLeave`) they leave: each scurries to the way in it can walk to soonest, springs up onto the wall and drops out of sight behind it (`ACheeseStrikeMouse::Leave`, `CheeseStrikeMice::OverTheEdge`), and is gone (`CheeseStrike.Play.TheMiceLeaveWhenTheCheeseIsGone`, and every map in `AfterTheMice`). To the players they are vermin: half a minute into a match the HUD counts down "VERMIN INVASION IN 0:30" (`CheeseStrikeMice::Warning`, `CountdownFrom`) and then says "THE VERMIN HAVE COME" (`CheeseStrikeHUD::VerminWords`), and nothing they read says mice; the code keeps the name. It blocks nothing but shots (its box blocks only the visibility channel), which reach it as the engine's point damage. Its body is the Black Rat from Fab, played by single animations (walk, run, sniffing to eat) chosen by a replicated state, and every machine plays its sounds by that state too (gnawing and crunches while it eats, squeaks now and then, a scream as it runs; from OpenGameArt, pitched down for its size). `ACheeseStrikeCheese` replicates (dormant until bitten or falling), shows its stage of being eaten in its mesh's custom primitive data (the cheese material's holes grow), and when eaten or falling makes what rested on it fall unless what else is under it holds it (`CheeseStrikeMice::IsHeld`: its middle inside what it rests on), down until it comes onto something that does. Cheese a map marks not edible (its walkable way through, round its starts) is never eaten, and wears red wax; every map in `CheeseStrikeRules::Maps` is checked to keep its starts on the ground and joined once the mice have eaten everything else (`CheeseStrike.Play.AfterTheMice`, after the mice have eaten it). The console's `CheeseStrikeCheeseLeft` counts the cheese left and `CheeseStrikeUnheld` lists any standing on nothing. Play tests and `tools/play.ps1` have no mice unless asked for (`?Mice=` in `FSession::Options`; `-Mice`). `CheeseStrikeMice` logs every mouse. A map may have a drop that kills (The Fondue Floor's vat of fondue): its kill height (`kit.kill_below`, World Settings' KillZ) kills whoever goes under it by the fall (`ACheeseStrikeCharacter::FellOutOfWorld`, `Rules/CheeseStrikeFalls.h`), the kill going to whoever hurt them in the five seconds before, else the feed and the death screen saying how ("fell into the fondue", from the place they fell into). A long fall onto anything hurts, as in Counter-Strike (`ACheeseStrikeCharacter::Landed`, by the speed it lands at; `CheeseStrikeFalls::DamageFor`): nothing for a drop up to 5.5 m (a jump down off the Kitchen's worktop or any 4 m level), then more the faster the landing, about a fifth of the health from the Market's belfry (7 m) and a third from the Grotto's gallery (8 m), and death from 16 m; every machine hears a thud (`MulticastHardLanding`), a kill by it is credited as a fall into the fondue is (else "fell"), in Execution it puts a player down as any hit would, and a bot never steps off an edge onto a drop that would hurt it (`UCheeseStrikeMovementComponent::CanWalkOffLedges`, `CheeseStrike.Play.ALongFallHurts`); there the bots never walk off an edge, a mouse never walks off one nor eats the floor from under itself or another mouse, leaps across a gap when it has eaten the floor round itself, and one that falls in anyway comes back over the edge a while later, and cheese that sinks under it is gone. The console's `CheeseStrikeEatCheese <share> [structure]` eats a share of the cheese at once, for looking at a map as the mice leave it.
- **Modes and streaks.** A match is played in the mode on its URL or picked in the lobby (`?Mode=FreeForAll`, `Deathmatch`, `Elimination`, `Execution`, `GunGame`, `KingOfTheHill` or `SoloKingOfTheHill`; `CheeseStrikeModes` in `Rules/CheeseStrikeModes.h` says what each is, how it is won, who takes a round and who may hurt whom, tested without a world), which the game state tells everyone (`ACheeseStrikeGameState::GetMode`, `HasTeams`). Every player has a side (`ACheeseStrikePlayerState::GetTeam`); only a team mode uses it: the teams' scores (`GetTeamScore`), friendly fire off (`ACheeseStrikeGameMode::CanHurt`, asked by the character's `TakeShot` and `TakeBlast`), bots that fight only the other side, and each side coming in at the starts the map tags for it (`PlayerStartTag` "Gouda" or "Mozza", as The Creamery's are) or else at its half of them; in a mode played in rounds the sides swap ends each round (`CheeseStrikeModes::StartSide`, `CheeseStrike.Play.TheSidesSwapStartsBetweenRounds`). Elimination is rounds of one life each (`?Rounds=`, `?RoundTime=`): the killed are out (`IsOut`) and watch a teammate (`ACheeseStrikeWatchCamera`) until a side is all out or the time runs out (shown on the score, told at 30 and 10 s left; in Execution, with someone down at the time, overtime until they are up or out), then after a pause everyone comes back at their side's starts. Execution is Elimination with a last stand (`Modes/CheeseStrikeLastStand`, a component of the character): a hit that would kill puts a player down instead (every time: up again, revived or by themself, they can go down again), with only the sidearm (the inventory's `RestrictTo`), harmed only by an enemy within a couple of metres, and shown on every machine lying on their back, propped on an elbow, the pistol out (`FCheeseStrikeDownedPose`, under Animation), and in the HUD's row and scoreboard as down. Down, the capsule is crouched (it covers the raised head and shoulders; the legs lie out ahead of it, and going down the server moves the body back from a wall just ahead, `MakeRoomToLieDown`); the view is kept to a cone toward the feet (`CheeseStrikeDowned::ClampView`, in `ACheeseStrikeCharacter::FaceRotation` on the machine that controls it, players' and bots' alike) and the body turns round after it slowly (`TurnBody`); it scoots on its back along itself, toward the feet only while the legs have room (`CheeseStrikeDowned::ScootInput` in the movement component's `ConstrainInputAcceleration`, `ScootSpeed`), the sideways keys turning it; the eyes (`Eyes`: where shots leave from, and bots' sight) are at the raised head, and shots find the torso and the legs where they lie (`FHitHistory`'s lying samples, `RayHitsBody`) and the head where its bone is, as they do standing (each hero's head a capsule fitted to it, `FBody::HeadLow`, `HeadHigh`, `HeadRadius`, on the server's posed body; `FHitHistory::RayHitsPlayer`); others see its aim to the side by `DownAimYawSent`; a bot down stays where it lies and fights; down, the weapon barely works (`CheeseStrikeModes::DownedWeapon`, through `ACheeseStrikeWeapon::FiringStats`: 0.35 of the damage, three times slower, wide from the first shot, kicking hard), bots' too, and its own player's view is dark, blurred past arm's length and swaying, the aim with it (`UCheeseStrikeLastStand::UpdateView`, the first-person camera's post-process and `CheeseStrikeModes::DownedSway`); held Interact (E) revives them from a teammate, the HUD's bar thick and green. A single press of Interact from an enemy executes them (`UCheeseStrikeLastStand::Execute`, `Rules/CheeseStrikeExecution.h`): a single knife thrust into the chest (held a moment and pulled out, with its own sounds, `tools/art/stab_sound.py`) or a head stomp at random, about 2.5 s, the executor put beside them (`SpotInBody`), both posed in code on every machine by `FCheeseStrikeExecutionPose` (`Animation/`, keyframed two-bone IK over the bones every hero has, after the downed pose), the executor's and the executed's own views blended out to a camera toward the feet on the far side (`CameraInBody`) and back, nobody in it moving or firing (`ACheeseStrikeCharacter::InExecution`, `TakesInput`) and neither hurt (`Intercept`); the one down dies at the blow (`KillAt`, "executed" in the feed; `WasExecuted` on their body, for the HUD), the stomp bursting the head into chunks of cheese on every machine. There is no bleeding out and no side out for being down: someone down is in until executed, and gets up by themself after `CheeseStrikeModes::SelfReviveTime` (20 s) with little health, the countdown shown to them and over them to anyone near (`UI/CheeseStrikeModeHUD`). `CheeseStrikeDown [name, enemy or mate]` on the host's console puts someone down, `CheeseStrikeRevive [name]` gets them up and `CheeseStrikeExecute [1 stab, 2 stomp] [name]` executes the nearest enemy down (`tools/play/downed.txt`, `downed_wall.txt`, `downed_row.txt`, `downed_view.txt`, `execution.txt`). Gun Game moves a player up `CheeseStrikeArsenal::GunGameLadder` at each kill, giving the step's weapon and nothing else (no changing weapons, no grenades; the knife only as the last step), with rounds without end to reload with (`ACheeseStrikeWeapon::MakeReserveEndless`; the HUD shows "/ ∞"), in `SetPlayerDefaults` and at once after a kill; a kill on the last step wins. King of the Hill (in two teams, or solo, everyone for themself) is played on one hill at a time, `ACheeseStrikeHill` (`Map/CheeseStrikeHill.h`, by the rules in `Rules/CheeseStrikeHills.h`), which the game mode puts up as the match begins and which goes round the map's spots (`ACheeseStrikeHillSpot`, three to five a map, placed by its script with `kit.hill_spots`), a minute at each, warning five seconds before it moves and showing where it goes: on the server a side scores a point a second while only its players stand in it (solo, a player alone in it), contested nobody does, each player's time in it is counted (`GetHillSeconds`, the scoreboard's "ON THE HILL"), being captured and moving are announced, and the kill limit is the points to win (`HillWon`); the killed come back as in Deathmatch, away from the hill (`CheeseStrikeHills::AwayFromHill`), and bots go to it, fighting on the way, and hold it (`ThinkAboutTheHill`). Every machine draws it as a ring and a column of light on the floor (`M_Hill`, `tools/art/hill_material.py`) in the colour of who holds it, a grey for nobody (`ACheeseStrikeHill::Neutral`), and the HUD marks it on the screen and the minimap with a strip over the score (`UI/CheeseStrikeHillHUD`); `CheeseStrikeMoveHill` on the host's console moves it on. Kills in a row earn streaks (`Rules/CheeseStrikeStreaks.h`: 3, 5 and 10), kept on the player state until the Streak key (Q) calls the next one in (`ACheeseStrikeGameMode::CallStreak`): the Unmanned Aerial Cheese (`Streaks/CheeseStrikeAerialCheese`; the game state's `IsRevealedTo`; a second one while the side's first is up adds its whole time to it, `CheeseStrikeStreaks::AddReveal`, `RevealStartedFor`; on a map whose starts are under a roof it flies under the roof, on the circle that runs into least, smaller under a low one: `FlyOver`, `CheeseStrikeStreaks::DroneHeight`), the Cheese Strike, its spot chosen on the strike map (`ACheeseStrikeHUD::DrawStrikeMap`, `UI/CheeseStrikeHUDStrike.cpp`: the minimap big in the middle, north up, the look moving a mark over it instead of the view, `ACheeseStrikeCharacter::MoveStrikeMark`, `ACheeseStrikePlayerState::MoveStrikeTarget`, the next shot calling it in on the floor there nearest the caller's feet, `ACheeseStrikeBombs::GroundNear`; `tools/play/strike_map.txt`), its seven wheels falling over a circle round it (`CheeseStrikeStreaks::StrikeArea`, `StrikeRadius`; bots still choose their spot themselves; indoors its wheels burst through the roof over their places and land on the floor at the mark's height, as the map's dots show: `ACheeseStrikeBombs::StrikeLanding`, finding roofs by `FCheeseStrikeOverhead`), and the Gouda Overload (both `Streaks/CheeseStrikeBombs`, wheels whose bursts are checked for line of sight and score for the caller); bots call theirs in too. The whistle and the siren are made in code (`Streaks/CheeseStrikeSynth`). What the modes and streaks show over the view is drawn by `UI/CheeseStrikeModeHUD`, which the HUD calls. `CheeseStrikeGiveStreak <1-3> [name or enemy]` on the host's console gives one for looking at it (`tools/play/strike.txt`, `streaks.txt`, `elimination.txt`).
- **Movement is predicted.** Anything that changes how the character moves must reach the server through the saved move (`CheeseStrikeMovementComponent`): a held key as a compressed flag, state as fields saved and restored with the move. Otherwise the server disagrees with what the player saw and snaps them back.
- **Editing assets from a script.** The editor's Python runs headless: `UnrealEditor-Cmd.exe <project> -ExecCmds="py <script>" -unattended -nullrhi` with `unreal.SystemLibrary.quit_editor()` at the script's end (the `-run=pythonscript` commandlet can't save a map). `print` goes nowhere; write to a file. The editor must be closed first: it holds the game module and the open level's file. A script can't rebuild a material that a C++ constructor loads, directly or through what it loads (a mesh's materials and their parents): what is loaded at the editor's start is rooted for good, and deleting its expressions asserts; so a class whose assets the scripts rebuild holds them as soft references and loads them in `BeginPlay` (`ACheeseStrikeMouse`). Setting a slot of an array read with `get_editor_property` changes a copy: build new structs and set the array back.
- **Packaging and sharing.** `powershell -ExecutionPolicy Bypass -File tools/package.ps1` packages a Development build for Windows (`BuildCookRun`; not Shipping, which would have Steam relaunch it as the test app id's game), plays it twice headless to check it (`tools/play/packaged_*.txt`: the menus, then a match on The Creamery with bots and mice), zips it without its debug symbols (kept in `..\CheeseStrikeBuilds\symbols\`) and copies the zip into `G:\My Drive\CheeseStrike Builds`, which Google Drive for desktop uploads, keeping the newest three. Only the maps in `Config/DefaultGame.ini`'s `MapsToCook` are cooked, with what they and the code reach, so a new map goes in that list as well as in `CheeseStrikeRules::Maps`; an asset that C++ holds only as a soft reference or loads by a path built at runtime isn't cooked, so its folder goes in `DirectoriesToAlwaysCook` (the mice's rat and sounds), and files read as files rather than assets (the menu's `Content/UI/`) are staged by `DirectoriesToAlwaysStageAsUFS`. The packaged game compiles as a unity build, so names in one file's anonymous namespace meet every other file's: give them names no parameter will have (`MousePitch`, not `Pitch`), or the package fails where the editor's build didn't.
- **The compiler is pinned.** Both targets in `Source/*.Target.cs` build with MSVC 14.50.35717, which Unreal 5.8 is made for; the 14.51 that Visual Studio 2026 updates bring in breaks the engine's headers. Change it there when Epic supports a newer one.
- **Working on several things at once.** `python tools/worktree.py add <name>` makes another working copy at `C:\Hamid\code\cs-wt\<name>` on a branch of that name, its `Content/` a worktree of the assets submodule (sharing its history and LFS objects; never `git submodule update` there, but `git -C Content checkout <commit>`), and `remove <name>` deletes it. Each copy builds its own binaries, and its tests and played games keep to themselves: `tools/run_tests.py` and `tools/play.ps1` give each copy its own build id (`-BuildIdOverride`, so that matches on the local network are found only by the same copy) and `play.ps1` its own port; play tests in the editor listen on a port of the copy's own too (`PlayTesting.cpp`), since a match that travels listens again on the port it was first given. Close only the games and editors of the copy being worked in.
- **Building from the command line.** `"C:\Program Files\Epic Games\UE_5.8\Engine\Build\BatchFiles\Build.bat" CheeseStrikeEditor Win64 Development -Project="<repo>\CheeseStrike.uproject" -WaitMutex -NoHotReloadFromIDE`. The last option lets the build go ahead while a game or editor of another working copy (`tools/worktree.py`) runs with Live Coding on, which otherwise stops every copy's build (`tools/run_tests.py` passes it); a game or editor of this copy holds its module's DLL, so close it first, or build from inside it with Live Coding.
- **Assets are in a private submodule.** This repository is public; `Content/` is the private `cheesestrike-assets` repository, because most assets may not be redistributed (Epic's template content under the Unreal Engine EULA, Fab content under its licences). Never commit an asset to this repository. A change to assets is a commit in `Content/` (on its `main`, pushed first), then a commit here that moves the submodule to it, in the same pull request as any code it goes with. Add a row to `Content/LICENSES.md` for every pack or file brought in, with its source and licence, and keep the folder each pack came in (`Content/<Pack>/`); in the same change give it a line in the game's credits (`Source/CheeseStrike/UI/CheeseStrikeCredits.cpp`, the front end's Credits page), naming it as its licence asks: a Creative Commons Attribution work by its title, author and licence (`CheeseStrike.Project.TheCreditsNameEveryone` checks every linked title in such a row). A new clone needs `git submodule update --init`, then `git lfs pull` inside `Content/`. Without the submodule the code still builds, but the project has nothing to open and the tests that check content fail.
- **Git LFS.** Binary files go through Git LFS in both repositories (`.gitattributes`). Run `git lfs install` once on a new machine. Don't commit `Binaries/`, `Intermediate/`, `Saved/` or the Visual Studio files; `.gitignore` leaves them out.
- **Scale.** The world is life size: Unreal centimetres and a 180 cm player. The Godot game was three times life size; [docs/unreal/design.md](docs/unreal/design.md#scale) says how its numbers convert.

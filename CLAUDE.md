# CheeseStrike: Gouda Overload

A multiplayer first-person shooter for Steam, made with Unreal Engine 5.8 in C++. The cover is cheese, and a minute into every match giant mice come and eat it. [docs/unreal/design.md](docs/unreal/design.md) is the whole game as a specification, and [docs/unreal/spike.md](docs/unreal/spike.md) is the plan the project is being built by. The game was first made in Godot; that version is kept at the `godot-final` tag, and its code there is the reference wherever the design document is not enough.

The project is at the repository's root: `CheeseStrike.uproject`, `Source/CheeseStrike/` (one game module), `Config/`, and `Content/`, which is the private `cheesestrike-assets` repository as a git submodule (see below). It began as Unreal's First Person template with its Shooter variant; `Config/DefaultEngine.ini` redirects the template's script package and classes to ours, and fixes two mistakes in the template's own content. The template's shooter level is the front end's backdrop (the menu's figure stands in it) and the play tests' playground, no map of the game's (the Proving Ground is one built by a script, `tools/art/build_proving.py`); its game mode override is cleared, so it plays with the game's own character, and its weapons, pickups and enemies are the template's and don't work with it. The game (never the editor) starts with virtual shadow maps off and turns them on once it has drawn 90 frames over 3 s, under the loading cover (`Rules/CheeseStrikeShadows.h`, `FCheeseStrikeModule`; the log says "Shadows: virtual shadow maps on after ..."): on an NVIDIA driver the GPU now and then faulted in their passes on a run's first frames and the game was gone (DXGI_ERROR_DEVICE_HUNG), and players' drivers will be older than ours.

## What the port keeps

The Godot game is the source of the design, not a thing to copy. Keep what Unreal and its First Person template do well (their input, movement feel, camera, scale and conventions) and port the game's ideas and tuning where they matter: the cheese that is cover and gets eaten by the mice that come partway through a match, so that a map opens up and the fight intensifies; the weapons' roles and roughly their numbers; the modes; the Overload. Don't port the Godot key bindings, speeds, scale or maps for their own sake. Words: a player is killed and scores kills, never knocked out. The Godot maps were placeholders; a placeholder map (the template's shooter level) does until there is a plan for how levels work.

## Testing rules

Every change follows both of these, in the same pull request as the change:

1. **Automated tests.** Assess whether the change's behavior can be covered by an automated test. If it can, write the test with the change. Tests are Unreal Automation tests in `Source/CheeseStrike/Tests/`, named `CheeseStrike.<Area>.<What it checks>`. Rules belong in plain C++ that a test can call without a world, as the Godot game kept its rules in plain classes. What needs the game running gets a test that plays it in the editor (`CheeseStrike.Play.*`, through `Tests/PlayTesting.h`): alone, or as a host with joiners in the same process for anything networked, each player driven by a play script (the same commands as `tools/play.ps1` uses) and the result read off the characters and the match state. Such a test takes ten to twenty seconds, so put several checks in one.
2. **Manual tests.** Assess whether `docs/manual-tests.md` needs rows added, changed or removed. Behavior that an automated test can't cover gets a row. A row that becomes covered by an automated test is deleted.

Say what you concluded in the pull request description, including when the answer is that no test or no manual-test change was needed.

Before pushing, run the tests: `python tools/run_tests.py`, which builds the editor and runs every `CheeseStrike` test headless, or `python tools/run_tests.py CheeseStrike.<Area>` for some of them. It fails if no test ran. The tests run without sound (`-nosound`); `--sound` runs them with the audio engine (on the PC's speakers), for a test that listens.

To see a change in the game itself, play it without a person: `powershell -ExecutionPolicy Bypass -File tools/play.ps1 -Script tools/play/<script>.txt -Tag <name>` starts the game rendering offscreen (no window, and the person at the PC keeps their mouse and keyboard; the editor must be closed), plays the script's commands through injected input (`Source/CheeseStrike/Dev/CheeseStrikePlayScript.h` lists them: hold and release actions, look, screenshot, state, a console command such as `CheeseStrikeDie`, quit), saves screenshots to `Saved/Screenshots/WindowsEditor/`, and traces the character's state ten times a second into `Saved/Logs/<name>.log` (`-TraceState`). `-ClientScript` starts a second game that joins the first, for two players, named by `-Name` and `-ClientName`; `-Extra "?listen?KillLimit=1"` passes the host's options. Read the numbers first (speed, eye height, crouched, health, ammunition, shots and hits), then the pictures. Write a script for what a change needs (the ones in `tools/play/` are examples), and give it `-StartAt X,Y,Z,Yaw` for a spot with room. The template's first-person rifle sits large and low in the view, so a thing on the floor ahead is often behind it: look to the side to see it.

## Working in this repo

- **Pull requests only.** `main` is protected: changes arrive through a pull request, merged by rebase. Keep each commit on a branch meaningful, since every one lands on `main`.
- **After merging, move on.** Once a pull request's checks have passed on an up-to-date branch, merge it and carry on.
- **Delete the local branch after merging.** A rebase merge rewrites the commits, so git won't see the branch as merged and `git branch -D` is needed. Return to an up-to-date `main`.
- **No AI attribution.** Don't add "Generated with Claude Code" to pull request descriptions or a `Co-Authored-By` trailer for Claude to commits.
- **C++ first.** Gameplay is written in C++ so that it can be read, edited and reviewed as text. Blueprints are for wiring assets to C++ classes (meshes, sounds, animation, the values a designer tunes), not for logic. A Blueprint can't be read in a diff, so say in the pull request what changed in one. Input actions and key bindings are made in code too (`Source/CheeseStrike/Input/`), not kept as assets. Assets the C++ needs (meshes, animation Blueprints) are found by path in constructors.

The game mode sets when it ends on the game state (`GetGoAt`, replicated, `IsFrozen`), before the characters come in; until then `ACheeseStrikeCharacter::CanAct` is false, so nobody moves, fires, changes weapons or calls in a streak (bots stand still too), but everyone can look round. The round's clock and the mice's arrival are counted from its end. The HUD draws its last three seconds big in the middle (`UI/CheeseStrikeHUDCountdown.cpp`: 3, 2, 1 under GET READY, then FIGHT; `CheeseStrikeStart::GlyphSeconds`, the seconds before them being the loadout page's to say), and the player controller sounds the lobby's tones for it (`SoundCountdown`). A fresh character is protected (`IsProtected`: unhurt, and bots don't aim at it) for `CheeseStrikeRules::SpawnProtection` seconds from the end of any count still running, or until it attacks: a shot, a knife stroke or calling in a streak (`EndProtection`, on the server; the replicated `ProtectedUntil` takes it to every machine). While protected it looks ghostly on every machine, its body, its own first-person arms and its weapons wearing `M_Ghost` (`Content/CheeseStrike/Effects`, made by `tools/art/ghost_material.py`: unlit, translucent, a pale blue-white wash with a brighter rim and rising bands) as an overlay material (`UpdateGhost`; the first-person arms and weapon with a softer rim), fading out over half a second as the protection ends. `CheeseStrikeProtect <seconds>` protects the player's character for looking at it (`tools/play/ghost.txt`, `ghost_server.txt` and `ghost_client.txt`).
- **The settings are the engine's, made the game's.** `UCheeseStrikeSettings` (`Source/CheeseStrike/Settings/`) is the engine's `UGameUserSettings` (`Config/DefaultEngine.ini` names it), kept in `GameUserSettings.ini`: the graphics (quality preset, window, resolution, VSync, frame rate limit, as the engine applies them; not the window in the editor; full screen, the window is the screen's own and the resolution picked is what the game is drawn at, `ScreenPercentageFor`, since DirectX 12 has no fullscreen of another size), and the game's own, each applied as it is set: the look's sensitivity (the mouse's and the stick's), its share while aiming and inverting it, the gamepad's aim assist (`ACheeseStrikePlayerController::LookScale`, used by the character's `DoAim`; a play script looks as the usual settings would), the field of view from the top of the view to the bottom, 75 by default as in the design (the camera manager turns it into the engine's across, for the screen's shape), and the master and effects volumes (`ApplySound`: the audio device's volume, and a sound mix over every sound class but the menu's, run again after each level loads), and the loadout's picks (the hero, the primary and the grenade's kind: `GetHero`, `GetPrimary`, `GetGrenade`, made on the loadout page). The settings page has a tab for each kind (`EOptionsTab`: the controls' table, aiming, sound, graphics), from the front end, the pause menu and the lobby: there Escape or a pad's Menu puts the lobby's menu over it (`EMenuPage::LobbyMenu`, `MakeLobbyMenu`: in the pages' panel on the left, as the pause menu is over a match, SETTINGS, LOADOUT and BACK; the lobby has no LOADOUT button of its own), whose SETTINGS and LOADOUT put the settings or the loadout page over the lobby in its place, Escape, B or Back going from them back to the menu and from the menu back to the lobby (`CheeseStrikeMenu::LobbyMenuKey`, `BackFromMenu`; `tools/play/lobby_menu.txt`); they are an overlay within the lobby's page (`CheeseStrikeMenu::LobbyOverlay`, `SettingsOverLobby`; the page shown stays the lobby), the lobby under them blurred and darkened as the game is under the pause menu and taking no press or focus, drawn by its own rules meanwhile and never afresh for them (`tools/play/lobby_settings.txt` and `lobby_settings_client.txt`; `lobby_loadout.txt` and `lobby_loadout_client.txt` for the loadout). A fresh install opens borderless at the screen's own size: `Config/DefaultGameUserSettings.ini` gives the engine the window mode and resolution it makes the window from (`UGameUserSettings::PreloadResolutionSettings`, which reads them only under the engine's own `Version`), `UCheeseStrikeSettings::LoadSettings` puts the settings' mode on the window to come once, in the game only (never the editor), and the log says what the window is ("Window: borderless, 2560 x 1440"); a GameUserSettings.ini the player's machine has saved keeps their choice (`CheeseStrike.Project.AFreshInstallPlaysBorderless`). The game's sound and music play on when its window loses focus: `[Audio] UnfocusedVolumeMultiplier` is 1.0 in `Config/DefaultEngine.ini`, where the engine's own 0 would mute it (`CheeseStrike.Project.TheSoundPlaysOnWithoutFocus`); nothing of the game's pauses sound on a lost focus, and a joiner's music is kept in step by the host's clock regardless (`UCheeseStrikeMusicSubsystem::Follow`). Their rules (ranges, the field of view across, the resolutions offered) are `CheeseStrikeSettings::*`, tested in `CheeseStrike.Rules.TheOptionsOpenAndKeepToTheirRanges`.
- **Matches go through Steam.** `Config/DefaultEngine.ini` puts the game on the Steam online service (test app id 480) with the Steam net driver; a match is a lobby that `UCheeseStrikeSessionSubsystem` offers, finds, joins and leaves (`Source/CheeseStrike/Sessions/`), driven for now by the console commands `CheeseStrikeHost [?KillLimit=..]`, `CheeseStrikeFind`, `CheeseStrikeJoin <n>` and `CheeseStrikeLeave`. Steam is only used by `-game` and packaged builds with the Steam client running; the editor, the tests and `tools/play.ps1` (unless given `-Steam`) use the Null service, which does the same over the local network, so the flow is tested in the editor and Steam itself is checked by hand on two PCs with two accounts. A second game on the same PC and account never gets the first's lobby data from Steam.
- **The HUD is drawn in code.** `ACheeseStrikeHUD` (`Source/CheeseStrike/UI/`) draws everything over the view on the canvas, in the engine's bold condensed Roboto through a runtime `UFont`, its shapes made of triangles (`CheeseStrikeHUDDraw`; the canvas has no rounded shapes, so a box with rounded corners is a polygon, `CheeseStrikeHUD::RoundedRect`, with as many steps to its arcs as their size needs, `CornerSteps`, and a picture in one, a Steam avatar, a fan of textured triangles, `RoundedPicture`; a shape standing alone, its corners, discs and rings, has a soft edge a pixel wide that fades it out where its outline crosses a pixel, so that curves are smooth rather than stepped, `SoftEdge`, `OutwardMiters`, `FShapes::SmoothPolygon`, while pieces that meet edge to edge, the minimap's, stay hard but where cut to its rounded corners), by rules that are plain functions tested without a world (`CheeseStrikeHUDRules.h`, `CheeseStrike.HUD.*`); it draws nothing under the front end and the lobby. The minimap is made from the level itself (`FCheeseStrikeMinimap`: every visible static mesh that blocks players, outlined from above by its collision shapes and shown by its height against the player's, and the cheese as it is now), so a new map needs nothing for it (its doors drawn as they are, open or shut), its corners rounded (pieces cut to them, `ClipToConvex`), the player a wedge of cheese pointing the way they face; north is +Y on every map, and the name of the place the player is in (`ACheeseStrikePlace::NameAt`) shows under it, as the place a body fell does in the kill feed. Each player's records are kept on their own machine (`Records/CheeseStrikeRecords`: `UCheeseStrikeRecordsSubsystem`, the save game slot "Records"), counted as the server tells it what they did (`ACheeseStrikePlayerController::ClientRecord`: kills, badges, streaks called in, revives, matches played and won) and saved at a match's end; they unlock the achievements of `Rules/CheeseStrikeAchievements.h` (tested in `CheeseStrike.Achievements.*`), shown for now as a toast at the top ("ACHIEVEMENT: HEAD CHEESE", `DrawAchievementToast`) and listed by `CheeseStrikeStats`; Steam's side waits for an App ID (`SetOnSteam`, and docs/unreal/design.md's list of what to make on Steamworks). Who is on whose side is the mode's (`ACheeseStrikeHUD::AreTeammates` asks `ACheeseStrikeGameState::AreTeammates`), the minimap shows each enemy where they were last known to be, never in real time and never for merely being in sight: firing (`NoteShot`) or swept by the side's Unmanned Aerial Cheese (`IsRevealedTo`, or `RevealEnemies` on this machine), moved at most once a second (`CheeseStrikeHUD::FEnemyMarks`), health is a cross and a row of blocks, never a number, anywhere (`HealthFills`, red and breathing when low with the red edges, what a hit took lingering a moment), the score at the bottom is `ScoreSummary` (a free-for-all's or the sides' and the round), in rounded tiles whose words never run into the score (`FitScoreBlock`: a side's name has the score made smaller for it first, then is cut with dots; `CheeseStrike.HUD.Streak` and `CheeseStrike.HUD.Score` show any for judging, `tools/play/hud_rounded.txt`), the list over the ammunition is `WeaponSlots` (the inventory's), and a player out of the round (`ACheeseStrikePlayerState::IsOut`) is struck through in the row, each tile framed in its side's colour (faded while dead, fainter out), with nothing under it, and a player down in Execution washed and framed in red-orange, "DOWN" across the tile's foot (`CheeseStrikeHUD::EStatus::Down`), and on the scoreboard (`DrawScoreboard`, `UI/CheeseStrikeHUDScoreboard.cpp`; - **Animation is composed in code.** `UCheeseStrikeAnimInstance` (`Source/CheeseStrike/Animation/`) builds the body's pose from the engine's standalone animation nodes (sequence and blend-space players, blends, mesh-space additives for the aim offsets, a slot for firing and reloading) and reads what the character is doing each frame; no animation Blueprint, so every machine's copy of a character animates alike and a new rig is a change of asset paths. Only nodes without folded properties are safe this way (the `_Standalone` players, `FAnimNode_TwoWayBlend`, `FAnimNode_MultiWayBlend`, `FAnimNode_ApplyMeshSpaceAdditive`, `FAnimNode_Slot`); the ordinary blend-space player, aim-offset and blend-by-bool nodes read Blueprint-only data and would fail in a packaged game. The rifle and its sounds are Lyra's (`Content/Characters/Heroes/`, `Content/Weapons/Rifle/`, `Content/Audio/`; `Content/LICENSES.md`), copied from the Lyra sample with their dependencies; the rifle is modelled along its Y axis and is turned a quarter turn in the hand bone `weapon_r`. The character puts on its player's every frame it lacks it (`UpdateBody`, from the replicated sides and ids, so every machine agrees; a fallen body keeps the one it fell in), and `CheeseStrikeBody <n> <side>` shows any of them, for looking (`tools/play/bodies.txt`). - **Maps are built by scripts.** A map is a Python script in `tools/art/` that builds its level from nothing in the editor (`build_creamery.py` for The Creamery, with `build_materials.py`, `cheese_material.py` and `wax_material.py` for its materials), so a map can be read and changed as text; its notes are in `docs/unreal/maps/`, and [docs/unreal/maps/principles.md](docs/unreal/maps/principles.md) is how to design and build one. The scripts are built from `tools/art/map_kit.py`: ground, walls, ramps, stairs, props, cheese in blocks, walls, floors and stacks, buildings of several storeys, tunnels, bridges, doors (`ACheeseStrikeDoor`, which open as anyone comes up to them), starts, the mice's ways in, named places (`ACheeseStrikePlace`), the navigation bounds and the light; `build_level` builds, checks and reports. Every box of cheese a script places (`kit.cheese` and all that build on it, edible and waxed alike) is a rounded block: a static mesh of its own size with its edges rounded off 7 cm, as a cut block of cheese is, standing 2 cm proud of its box collision on every face so that blocks laid edge to edge run together and show a shallow seam rather than a slit (`tools/art/block_mesh.py`: one mesh per distinct size the maps use, made in the editor the first time a map asks for it and kept in `/Game/CheeseStrike/Blocks` as `SM_CheeseBlock_<x>x<y>x<z>`, its collision the plain box of the size asked for, so the minimap's outlines, the mice's holds and where shots land are as they were, and its bounds the mesh's own, all of what is drawn (the game measures a block by its collision, `ACheeseStrikeCheese::GetBlockBox`, which its `GetComponentsBoundingBox` gives, never by its bounds: bounds pulled inside what is drawn had the renderer's occlusion test find a block hidden behind its own faces, and blocks vanished for a frame now and then, which flickered, until wave 16; `tools/art/block_overlaps.py` lists, for every map, the faces that lie in one plane and overlap, which would z-fight); the cheese material carves its holes in world space, so the eaten stages read on them as on the cube; `wheel_mesh.py`'s SM_CheeseWheel does the same for wheels). A script saves a map through `map_kit.save_level`, which takes the editor's navigation mesh out of it first: the editor spawns a RecastNavMesh with an empty tile grid as a level with navigation bounds is opened or built and fills it over the frames to come, which a script never gives it, and a mesh saved so counts as built to the game (`RuntimeGeneration=Dynamic` keeps what was saved and rebuilds only where something changes), so every map saved by `delete_unused_weapons.py` in wave 15 left its bots and mice nowhere to walk; with none saved the game builds the mesh afresh as the level starts (`CheeseStrike.Project.NoMapKeepsAnUnbuiltNavigationMesh` reads every map's export table for one). `tools/art/map_picture.py` takes a map's picture for the lobby. Its art is free Fab content: Fab's web page downloads a listing's files (a Megascans surface's texture set, a model's FBX), kept outside the repository in `C:\Hamid\code\FabDownloads`, and `import_fab.py` imports what the maps use into `Content/Fab/` (box collision, Nanite, textures cut to 2K or 1K); a listing that only comes in Unreal's own format needs the Epic Games Launcher, which a script can't drive. Surfaces are drawn on the maps' blocks from world space (`M_Surface`); a model that stands for cover is scaled to fill its block. Every block of cheese is an `ACheeseStrikeCheese` (`Source/CheeseStrike/Map/`) naming the structure it belongs to, for the mice to eat. What hangs in cheese (a door in a wall of it, a lamp under a roof of it: `attach_to=<structure>` on `kit.door`, `interior_lamp`, `point_lamp`, `point_light` and `prop`, or `kit.hang`, which tags the actor `HungOn:<structure>`; `building` and `tunnel` do it for their doors and the lamps under their cheese roofs) goes with the cheese round it: as the level starts the subsystem finds the blocks of that structure touching the thing's bounds or within 150 cm of them (`CheeseStrikeMice::HungReach`, `IsRoundHung`: a door's wall either side and the lintel over it, not the far end of the wall), and once all of those are eaten or have fallen out of reach it shrinks and falls away and is gone, collision and all, though the rest of the structure stands; a thing with no block round it (a lamp hung in the air under a cheese roof) goes once every block of the structure is eaten; on every machine from the cheese it already has (`UCheeseStrikeHungSubsystem`, `CheeseStrikeMice::IsHungOnEatenCheese`, tested in `CheeseStrike.Mice.WhatHangsInCheeseGoesWithIt`; `CheeseStrike.Play.AfterTheMice` checks each map's are gone once the cheese is; `tools/play/hung_door.txt` eats only the cheese round the Curing House's door with `CheeseStrikeEatCheese 1 CuringHouseGouda <x> <y> <z> <radius>` and looks at the door gone while the house stands; the console's `CheeseStrikeHung` lists what hangs, with the blocks round each and how many are left). A script that saves a level must check the level it has open: the editor opens on the shooter level, and a failed open builds into that. The Practice Range (`tools/art/build_range.py`, [docs/unreal/maps/range.md](docs/unreal/maps/range.md), `Rules/CheeseStrikeRange.h`) is a yard for trying the weapons, for one player from the front end's PRACTICE only (the lobby's map list leaves it out, `CheeseStrikeRules::IsOffered`, `MapsOffered`, though it stays in `Maps` for the URL, the cook and PRACTICE, and a match hosted on it, `?listen`, plays the default map instead, the game mode logging why: `MapForMatch`, `IsHosted`): a stand for every weapon that lies on one, each instant (`kit.pickup(instant=True)`: taken, it is back at once), markers at 5, 10, 20 and 40 m (`kit.text_sign`), a wall of cheese targets that shots break and that grow back (`kit.target`, `ACheeseStrikeTarget`, not cheese the mice eat), and four dummies at its dummy spots (`kit.dummy_spot`): bots with `?BotSkill=dummy` (`ACheeseStrikeBotController::IsDummy`) that never aim or fire and come back where they stood (`ACheeseStrikeGameMode::ChooseDummySpot`), the 5 m and 40 m ones standing still, the 10 m one strafing left and right in its lane at a walk and the 20 m one at a sprint, for trying the Gouda Overload's slowdown on (`CheeseStrikeRange::DummyMotion`, `StrafeWay`, `ACheeseStrikeBotController::StrafeAsDummy`); it has no cheese, so `AfterTheMice` checks only its stands (`CheeseStrike.Play.ThePracticeRangeNeverEmpties` plays it). The Proving Ground (`tools/art/build_proving.py`, [docs/unreal/maps/proving.md](docs/unreal/maps/proving.md)) is the plainest map of the game's: a symmetric arena of 60 by 40 m, a flat floor, each side's starts behind a screen of waxed cheese, rounded cheese walls and stacks to fight round in the lanes and at the middle, two low platforms of waxed cheese, four stands, three hill spots on the middle line, the mice over the north and south walls; it took the template's shooter level's place in `CheeseStrikeRules::Maps` and `MapsToCook` (the shooter level stays there for the front end). Gruyère Grotto's two spans are bridges of cheese on beams of cheese (`kit.bridge(cheese_beams=True)`, their rope rails and posts hung on them), so that once the mice have eaten them nothing reaches the Spine's arch and the Roquefort Rifle on its perch there is stranded, by design: its stand is `kit.pickup(stranded=True)`, tagged `Stranded`, which the stands' checks (below) take as a stand with a way to it before the mice only.

The choice is kept in the settings (`UCheeseStrikeSettings::GetPrimary`, `GetGrenade`, `GetHero`, in GameUserSettings.ini) and made on the loadout page (`EMenuPage::Loadout`, `SCheeseStrikeMenu::MakeLoadout`): HERO as the four heroes' portraits (`Content/UI/Heroes/`, head and shoulders cropped by `tools/art/hero_portraits.py` from `tools/play/hero_portraits.txt`'s screenshots), PRIMARY as the weapons' HUD icons with their names, PRIMARY's icons drawn at their own shape (`SCheeseStrikeFitImage`, in a box of `WeaponIconAspect`), GRENADE as the two kinds' pictures (`Content/UI/Loadout/`, rendered lit from the grenade's own model in its two looks by `tools/art/grenade_icons.py` in Blender), the one picked of each ringed in cheese, every item focusable for a pad, and right of them the hero view (`ACheeseStrikeHeroView`, `MakeHeroView`): the hero picked holding the primary picked, whole from head to foot and turning slowly, against a plain soft white-grey fog and nothing of the level, a figure of its own high over the level inside a sphere of the fog (`M_HeroBackdrop`, `tools/art/hero_backdrop.py`) captured into a picture while the page shows (`ACheeseStrikePlayerController::GetHeroPicture`), wherever the page is opened; opened from the front end's LOADOUT button (the figure there stands aside while it shows; `tools/play/loadout.txt`, `menus_w16.txt`), from the lobby's menu, host and joiners alike (an overlay on the lobby, as the settings are), and of itself as a count-in begins in a mode with a loadout (`ACheeseStrikePlayerController::IsLoadoutOffered`, `CheeseStrikeLoadout::OffersPage`: the HUD and its count show through, the page says "THE MATCH BEGINS IN n" or "THE ROUND BEGINS IN n", and OK, Enter, B or Escape put it away for that count, `DismissLoadout`; `tools/play/loadout_countin.txt`). The player's machine sends all three to the server whenever its player state lacks them and the rules allow (`SendLoadout`, `ServerSetLoadout`; `WantedLoadout` is the settings', or the console's `CheeseStrikeLoadout <words>` (a primary, a grenade's kind, a hero, in any order; none for the settings' again) and `CheeseStrikeHero <name>`, kept by `UCheeseStrikeLoadoutChoice`, which the tests pick with); the server takes it onto the player state (`ACheeseStrikePlayerState::SetLoadout`, replicated) only while `MayChange` says so, logging a refusal otherwise, and from there the hero is worn at the next spawn (`UpdateBody`) and the primary and the grenades' kind come with the next character (`UCheeseStrikeInventory::GiveSpawnLoadout`, `UCheeseStrikeLoadouts::PrimaryFor`, `GrenadeFor`, `UCheeseStrikeGrenades::SetKind`), or at once during a count-in, the body swapping while everyone is held (`TakeChoice`, on a character still protected). Bots wear the rota hero and carry the default loadout (`CheeseStrike.BotPrimary` for watching one weapon in their hands). `CheeseStrike.Play.ALoadoutPickedInTheLobbyOrTheCountInIsCarried` plays a joiner's pick in the lobby and the host's during the count-in, and a pick refused mid-match.
- **Weapons lie on stands.** Every map has four to eight weapon stands at fixed spots (`ACheeseStrikePickup`, `Weapons/CheeseStrikePickup.*`, placed by the maps' scripts with `kit.pickup`, which keeps the cheese under each so the mice never eat its floor), each a low plinth with a pad glowing in the one cheese gold every weapon has (`CheeseStrikePickups::WorthColour`; what a gun is worth, `Worth`, only decides where it lies and what bots want) and the weapon floating and turning over it (two guns both, 24 cm apart, `PairApartOnStand`; 14 lying on the floor); the better at the riskier spots, both sides reaching them alike. The rules are `Rules/CheeseStrikePickups.h` (tested in `CheeseStrike.Pickups.*`): everyone comes in with the weak Colby Carbine; nothing is taken by walking over it: a press of Interact (E, LB) near it takes the stand's weapon, the HUD naming the swap (`UI/CheeseStrikePickupHUD`), and one's own weapon tops up its rounds (`UCheeseStrikeInventory::PressForPickup`, `TakePickup`, `SwapPrimary`, in hand at once and drawn from the moment it was taken, as a change of weapons is, its rising in view and the body's draw, on every machine: `ACheeseStrikeWeapon::SetArrived`, `ArrivedAt`, sent with the new weapon, and the inventory's `ShownWeapon`, since another machine's copy of the slot simply has a new weapon in it); any take, a weapon or its rounds, tops up the sidearm's reserve too (the Curd Pistol has a magazine of 12 and 36 besides since wave 16, no longer endless: `CheeseStrikePickups::SidearmTopUp`, `RoundsFull`, so that one's own weapon is offered for its rounds while the pistol is short); the primary carried drops to the floor with its rounds, the Carbine too, an `ACheeseStrikePickup` of its own (`Drop`, `IsDropped`: no plinth, lying on its side) that anyone takes with the same press, gone after 20 s (blinking at the end), at most 12 about (`CheeseStrikePickups::DroppedSeconds`, `MostDropped`), and cleared at a new round; `CheeseStrikeStand <weapon>` and `CheeseStrikeDropWeapon <weapon>` put one ahead for looking (`tools/play/pickup_looks.txt`). The server owns the stands: taken, one is empty for 60 s (the replicated `BackAt`; `CheeseStrike.PickupSeconds` for the tests; a stand the map makes instant, the Practice Range's, is back at once, `IsInstant`, `CheeseStrikePickups::BackAt`), every machine showing its weapon as a ghost (`M_Ghost`) over a dim pad and the HUD the seconds over it; a new round puts every weapon back; Gun Game has none (hidden). The minimap shows them as diamonds. Bots go for a better weapon near them, on a stand or the floor, with nobody in sight, and press for it there (`ThinkAboutPickups`, `CheeseStrikePickups::BotWants`). `CheeseStrike.Play.AWeaponIsTakenFromItsStandAndComesBack`, `GunGameHasNoPickups` and `ABotGoesForABetterWeapon` play them, and `CheeseStrike.Play.AfterTheMice` checks every map's (`Tests/PickupChecks.h`: how many, fair, the better riskier, room and a way to each, clear of King of the Hill's spots; after the mice a floor under each and a way to it still, but for a stand tagged `Stranded` (the Grotto's Roquefort in the Spine's arch, above), which must then have none).
- **Bots are played in code.** `ACheeseStrikeBotController` plays a bot on the server, by the rules in `Rules/CheeseStrikeBots.h` (the design's skill table, aim error that steadies as it tracks, turning no faster than its skill, bursts and rests, a sight cone, keeping to its weapon's range), tested without a world in `CheeseStrike.Bots.*`. It sees by line traces, walks the navigation mesh (`Config/DefaultEngine.ini` builds it when a level starts, in the level's `NavMeshBoundsVolume`, and rebuilds it where the level changes; a play test of the level the editor has open builds it afresh in `StartPlaying`, since playing copies the editor's, which may be unfinished), and works its character as a player does: path following and movement input, its control rotation for the view, the character's `Do*` actions for the trigger, the sights, reloading and changing weapons (the primary it took from a stand, the pistol when the magazine runs out with someone near, the knife up close: `CheeseStrikeBots::ChooseWeapon`); the weapon aims a bot's shots by its control rotation. In Execution a bot never fights someone down: it executes an enemy down in reach at once, goes to execute one further off (`ThinkAboutTheDown`, `CheeseStrikeBots::GoesToExecute`: even mid-fight, for one nearer than the enemy it fights), coming from outside their aim and swerving while in it (`CheeseStrikeBots::FinishApproach`), as widely as the floor either side allows (measured by a navigation raycast; straight on in a hallway, `SwerveWidth`), its goal kept on the navigation mesh and its path asked for at most every 0.3 s (`ShouldRepath`), and with no enemy in sight revives a teammate down by holding Interact; roaming, bots keep away from their teammates and where they are going (`CheeseStrikeBots::RoamScore`), so that a side spreads out; a bot that gets nowhere is stuck by where it is, not its velocity. No behaviour tree or blackboard assets. The host picks the skill in the lobby (`?BotSkill=`). Play tests get no bots unless they ask for them (`?Bots=` in `FSession::Options`); `tools/play.ps1 -Bots` fills a match with them.
- **The mice eat the cheese.** Three minutes into a match (`?MiceAt=` for sooner, `?Mice=0` for none) the game mode sends in one mouse for every 25 blocks of edible cheese, three to twenty-four, at the level's `MouseEntry` points (on top of its edge, facing in; a map without them or without cheese has none). `ACheeseStrikeMouse` (`Source/CheeseStrike/Map/`, by `Rules/CheeseStrikeMice.h`) runs on the server: it goes for the cheapest block (distance, plus four times its height, plus more for another mouse's, and more near the other mice and their blocks, so that they spread over the map: `CheeseStrikeMice::CrowdCost`), walks the navigation mesh to a spot beside it (never on top of it) with its own path following (finding its way afresh every few seconds, and when it has fallen) and keeps to the ground (falling when what it stood on is eaten), bites every half second, at a pace that has every map eaten bare about eight minutes after the mice come, steadily (`CheeseStrikeMice::Pace`: a bite is 100 times the cube of the share of the cheese left over the share a steady eating would have left by then, from 0.15 to four times, a block at a bite; the game mode gives each mouse the schedule, `SetSchedule`, and logs how they are getting on every ten seconds, `Mice: ... blocks left`), so `CheeseStrike.Play.AfterTheMice` plays every map's mice (at a fixed step, faster than real time) and checks all is eaten within a minute and a half, not most of it in the first 25 s, and the mice eating spread out, runs from shots that hurt it by 300 (and then eats away from there, on the far side of the map's middle if it can, for a minute or four blocks: `CheeseStrikeMice::ScareCost`), and gives up on a block it makes no progress on. It reaches 2.6 m across and 4 m up (rearing up to an upper storey's wall). Cheese it can't walk to it walks as near as it can to and leaps onto (`LeapTo`: across a gap, up to a floor no stairs reach, or onto a block standing alone, which it then eats from on top and falls with, `EatsUnderfoot`); and 40 s after they came (`CheeseStrikeMice::BoundAfter`) a mouse with nothing it can walk or leap to bounds straight to the nearest such cheese (`BoundTo`). One that has bitten nothing for 15 s comes in again at another way in; one cut off, on an island of floor it ate round itself or anywhere it can walk to the ground inside no way in from (`ACheeseStrikeMouse::LeadsOut`: Gruyère Grotto's arch through the Spine once its bridges are eaten), leaps down within seconds onto floor that leads out, up to 5.5 m below, never through rock (`LeapOut`, `IsClearFlight`, which every leap keeps to; `CheeseStrike.Play.MiceLeftInTheGrottosArchGetOut`, `tools/play/grotto_arch.txt`; the console's `CheeseStrikeMouseTo <n> <x> <y> <z>` puts a mouse anywhere). Once no edible cheese is left (`CheeseStrikeMice::ShouldLeave`) they leave: each scurries to the way in it can walk to soonest, springs up onto the wall and drops out of sight behind it (`ACheeseStrikeMouse::Leave`, `CheeseStrikeMice::OverTheEdge`), and is gone (`CheeseStrike.Play.TheMiceLeaveWhenTheCheeseIsGone`, and every map in `AfterTheMice`). To the players they are vermin: half a minute into a match the HUD counts down "VERMIN INVASION IN 0:30" (`CheeseStrikeMice::Warning`, `CountdownFrom`) and then says "THE VERMIN HAVE COME" (`CheeseStrikeHUD::VerminWords`), and nothing they read says mice; the code keeps the name. It blocks nothing but shots (its box blocks only the visibility channel), which reach it as the engine's point damage. Its body is the Black Rat from Fab, played by single animations (walk, run, sniffing to eat) chosen by a replicated state, and every machine plays its sounds by that state too (gnawing and crunches while it eats, squeaks now and then, a scream as it runs; from OpenGameArt, pitched down for its size). `ACheeseStrikeCheese` replicates (dormant until bitten or falling), shows its stage of being eaten in its mesh's custom primitive data (the cheese material's holes grow), and when eaten or falling makes what rested on it fall unless what else is under it holds it (`CheeseStrikeMice::IsHeld`: its middle inside what it rests on), down until it comes onto something that does. Cheese a map marks not edible (its walkable way through, round its starts) is never eaten, and wears red wax; every map in `CheeseStrikeRules::Maps` is checked to keep its starts on the ground and joined once the mice have eaten everything else (`CheeseStrike.Play.AfterTheMice`, after the mice have eaten it). The console's `CheeseStrikeCheeseLeft` counts the cheese left and `CheeseStrikeUnheld` lists any standing on nothing. Play tests and `tools/play.ps1` have no mice unless asked for (`?Mice=` in `FSession::Options`; `-Mice`). `CheeseStrikeMice` logs every mouse. A map may have a drop that kills (The Fondue Floor's vat of fondue): its kill height (`kit.kill_below`, World Settings' KillZ) kills whoever goes under it by the fall (`ACheeseStrikeCharacter::FellOutOfWorld`, `Rules/CheeseStrikeFalls.h`), the kill going to whoever hurt them in the five seconds before, else the feed and the death screen saying how ("fell into the fondue", from the place they fell into). A long fall onto anything hurts, as in Counter-Strike (`ACheeseStrikeCharacter::Landed`, by the speed it lands at; `CheeseStrikeFalls::DamageFor`): nothing for a drop up to 5.5 m (a jump down off the Kitchen's worktop or any 4 m level), then more the faster the landing, about a fifth of the health from the Market's belfry (7 m) and a third from the Grotto's gallery (8 m), and death from 16 m; every machine hears a thud (`MulticastHardLanding`), a kill by it is credited as a fall into the fondue is (else "fell"), in Execution it puts a player down as any hit would, and a bot never steps off an edge onto a drop that would hurt it (`UCheeseStrikeMovementComponent::CanWalkOffLedges`, `CheeseStrike.Play.ALongFallHurts`); there the bots never walk off an edge, a mouse never walks off one nor eats the floor from under itself or another mouse, leaps across a gap when it has eaten the floor round itself, and one that falls in anyway comes back over the edge a while later, and cheese that sinks under it is gone. The console's `CheeseStrikeEatCheese <share> [structure or *] [x y z radius]` eats a share of the cheese at once (of one structure, or only the blocks within a radius of a point), for looking at a map as the mice leave it.
- **Modes and streaks.** A match is played in the mode on its URL or picked in the lobby (`?Mode=FreeForAll`, `Deathmatch`, `Elimination`, `Execution`, `GunGame`, `KingOfTheHill` or `SoloKingOfTheHill`; `CheeseStrikeModes` in `Rules/CheeseStrikeModes.h` says what each is, how it is won, who takes a round and who may hurt whom, tested without a world), which the game state tells everyone (`ACheeseStrikeGameState::GetMode`, `HasTeams`). Every player has a side (`ACheeseStrikePlayerState::GetTeam`); only a team mode uses it: the teams' scores (`GetTeamScore`), friendly fire off (`ACheeseStrikeGameMode::CanHurt`, asked by the character's `TakeShot` and `TakeBlast`), bots that fight only the other side, and each side coming in at the starts the map tags for it (`PlayerStartTag` "Gouda" or "Mozza", as The Creamery's are) or else at its half of them; in a mode played in rounds the sides swap ends each round (`CheeseStrikeModes::StartSide`, `CheeseStrike.Play.TheSidesSwapStartsBetweenRounds`). Elimination is rounds of one life each (`?Rounds=`, `?RoundTime=`): the killed are out (`IsOut`) and watch a teammate (`ACheeseStrikeWatchCamera`) until a side is all out or the time runs out (shown on the score, told at 30 and 10 s left; in Execution, with someone down at the time, overtime until they are up or out), then after a pause everyone comes back at their side's starts. Execution is Elimination with a last stand (`Modes/CheeseStrikeLastStand`, a component of the character): a hit that would kill puts a player down instead (every time: up again, revived or by themself, they can go down again), with only the sidearm (the inventory's `RestrictTo`), harmed only by an enemy within a couple of metres, and shown on every machine lying on their back, propped on an elbow, the pistol out (`FCheeseStrikeDownedPose`, under Animation), and in the HUD's row and scoreboard as down. Down, the capsule is crouched (it covers the raised head and shoulders; the legs lie out ahead of it, and going down the server moves the body back from a wall just ahead, `MakeRoomToLieDown`); the view is kept to a cone toward the feet (`CheeseStrikeDowned::ClampView`, in `ACheeseStrikeCharacter::FaceRotation` on the machine that controls it, players' and bots' alike) and the body turns round after it slowly (`TurnBody`); it scoots on its back along itself, toward the feet only while the legs have room (`CheeseStrikeDowned::ScootInput` in the movement component's `ConstrainInputAcceleration`, `ScootSpeed`), the sideways keys turning it; the eyes (`Eyes`: where shots leave from, and bots' sight) are at the raised head, and shots find the torso and the legs where they lie (`FHitHistory`'s lying samples, `RayHitsBody`) and the head where its bone is, as they do standing (each hero's head a capsule fitted to it, `FBody::HeadLow`, `HeadHigh`, `HeadRadius`, on the server's posed body; `FHitHistory::RayHitsPlayer`); others see its aim to the side by `DownAimYawSent`; a bot down stays where it lies and fights; down, the weapon barely works (`CheeseStrikeModes::DownedWeapon`, through `ACheeseStrikeWeapon::FiringStats`: 0.35 of the damage, three times slower, wide from the first shot, kicking hard), bots' too, and its own player's view is dark, blurred past arm's length and swaying, the aim with it (`UCheeseStrikeLastStand::UpdateView`, the first-person camera's post-process and `CheeseStrikeModes::DownedSway`); held Interact (E) revives them from a teammate, the HUD's bar thick and green. A single press of Interact from an enemy executes them (`UCheeseStrikeLastStand::Execute`, `Rules/CheeseStrikeExecution.h`): a single knife thrust into the chest (held a moment and pulled out, with its own sounds, `tools/art/stab_sound.py`) or a head stomp at random, about 2.5 s, the executor put beside them (`SpotInBody`), both posed in code on every machine by `FCheeseStrikeExecutionPose` (`Animation/`, keyframed two-bone IK over the bones every hero has, after the downed pose), the executor's and the executed's own views blended out to a camera toward the feet on the far side (`CameraInBody`) and back, nobody in it moving or firing (`ACheeseStrikeCharacter::InExecution`, `TakesInput`) and neither hurt (`Intercept`); the one down dies at the blow (`KillAt`, "executed" in the feed; `WasExecuted` on their body, for the HUD), the stomp taking the head off on every machine, with the jet of cheese from where it was (the cheese players bleed, above; no chunks: those are the Cheese Grater's supercombine's alone, `UCheeseStrikeLastStand::ShowCheeseBurst`). There is no bleeding out and no side out for being down: someone down is in until executed, and gets up by themself after `CheeseStrikeModes::SelfReviveTime` (20 s) with little health, the countdown shown to them and over them to anyone near (`UI/CheeseStrikeModeHUD`). `CheeseStrikeDown [name, enemy or mate]` on the host's console puts someone down, `CheeseStrikeRevive [name]` gets them up and `CheeseStrikeExecute [1 stab, 2 stomp] [name]` executes the nearest enemy down (`tools/play/downed.txt`, `downed_wall.txt`, `downed_row.txt`, `downed_view.txt`, `execution.txt`). Gun Game moves a player up `CheeseStrikeArsenal::GunGameLadder` at each kill, giving the step's weapon and nothing else (no changing weapons, no grenades; the knife only as the last step), with rounds without end to reload with (`ACheeseStrikeWeapon::MakeReserveEndless`; the HUD shows "/ ∞"), in `SetPlayerDefaults` and at once after a kill; a kill on the last step wins. King of the Hill (in two teams, or solo, everyone for themself) is played on one hill at a time, `ACheeseStrikeHill` (`Map/CheeseStrikeHill.h`, by the rules in `Rules/CheeseStrikeHills.h`), which the game mode puts up as the match begins and which goes round the map's spots (`ACheeseStrikeHillSpot`, three to five a map, placed by its script with `kit.hill_spots`), a minute at each, warning five seconds before it moves and showing where it goes: on the server a side scores a point a second while only its players stand in it (solo, a player alone in it), contested nobody does, each player's time in it is counted (`GetHillSeconds`, the scoreboard's "ON THE HILL"), being captured and moving are announced, and the kill limit is the points to win (`HillWon`); the killed come back as in Deathmatch, away from the hill (`CheeseStrikeHills::AwayFromHill`), and bots go to it, fighting on the way, and hold it (`ThinkAboutTheHill`). Every machine draws it as a ring and a column of light on the floor (`M_Hill`, `tools/art/hill_material.py`) in the colour of who holds it, a grey for nobody (`ACheeseStrikeHill::Neutral`), and the HUD marks it on the screen and the minimap with a strip over the score (`UI/CheeseStrikeHillHUD`); `CheeseStrikeMoveHill` on the host's console moves it on. Kills in a row earn streaks (`Rules/CheeseStrikeStreaks.h`: 3, 5 and 10), kept on the player state until the Streak key (Q) calls the next one in (`ACheeseStrikeGameMode::CallStreak`): the Unmanned Aerial Cheese (`Streaks/CheeseStrikeAerialCheese`; the game state's `IsRevealedTo`; a second one while the side's first is up adds its whole time to it, `CheeseStrikeStreaks::AddReveal`, `RevealStartedFor`; on a map whose starts are under a roof it flies under the roof, on the circle that runs into least, smaller under a low one: `FlyOver`, `CheeseStrikeStreaks::DroneHeight`), the Cheese Strike, its spot chosen on the strike map (`ACheeseStrikeHUD::DrawStrikeMap`, `UI/CheeseStrikeHUDStrike.cpp`: the minimap big in the middle, north up, the look moving a mark over it instead of the view, `ACheeseStrikeCharacter::MoveStrikeMark`, `ACheeseStrikePlayerState::MoveStrikeTarget`, the next shot calling it in on the floor there nearest the caller's feet, `ACheeseStrikeBombs::GroundNear`; `tools/play/strike_map.txt`), its seven wheels falling over a circle round it (`CheeseStrikeStreaks::StrikeArea`, `StrikeRadius`; bots still choose their spot themselves; indoors its wheels burst through the roof over their places and land on the floor at the mark's height, as the map's dots show: `ACheeseStrikeBombs::StrikeLanding`, finding roofs by `FCheeseStrikeOverhead`), its wheels' bursts checked for line of sight and scoring for the caller, and the Gouda Overload (both `Streaks/CheeseStrikeBombs`): after the siren and three seconds' warning, melted gouda splats every living enemy of the caller at once, wherever they are, down or standing (`ACheeseStrikeCharacter::Splat`: their view smeared yellow with drips, `ACheeseStrikeHUD::DrawGoo`, melted gouda on the floor at their feet on every machine while they are slowed, a big glossy puddle as it lands and then a trail of smaller ones every 35 cm or 1.2 s, each spreading, staying and fading, smaller as the goo thins (`Rules/CheeseStrikeGoo.h`, `CheeseStrike.Goo.*`; `Effects/CheeseStrikeGooSplats`, the blood's splat decal in gouda's colours; `tools/play/w16_goo.txt`), and their speed cut to a quarter, coming back in a straight line over 15 s, no sprint or slide under 60% of it, `CheeseStrikeStreaks::GooFactor`, `MaySprintInGoo`; the movement component works it out on both sides from the replicated `SplatAt` and `GooUntil` and the server's clock, as it does the caller's haste, so the moves agree), and its caller at once runs 1.5 times as fast for 30 s (`Hasten`, `HasteAt`) and has the Gouda Gatling in hand (`UCheeseStrikeInventory::GiveSpecial`: a minigun of molten cheese that spins up for 0.4 s and fires twenty a second, 200 rounds and no reload, yellow tracers, `FWeaponLook::Tracer`; the HUD shows its rounds and the time it has left), their primary kept out of sight and given back when its rounds or its 30 s run out (`EndSpecial`); `CheeseStrike.OverloadSeconds` shortens all three for the play tests (`CheeseStrike.Play.StreaksAreCalledInAndScoreForTheirCallers`), and `tools/play/streaks.txt` and `gatling.txt` look at them; bots call theirs in too. The whistle and the siren are made in code (`Streaks/CheeseStrikeSynth`): the Gouda Overload's an air-raid siren heard across a town, one slow wail of two tones a minor third apart rising, held and winding down with no warble (`SirenPitch`), the motor's hum under it, dulled by the distance with an echo and a reverberant tail (`CheeseStrike.Feedback.Siren`). A voice on the command net tells each player what concerns them (`Rules/CheeseStrikeVoice.h`, tested in `CheeseStrike.Voice.*`): a streak called in by their side or the enemy's ("UAC online", "Enemy Cheese Strike inbound", "Gouda Overload incoming": `ACheeseStrikeGameState::SpeakStreak`), the vermin coming, a teammate's kill now and then ("Enemy down", in a mode of sides), a round won or lost and the match's Victory or Defeat (`ACheeseStrikePlayerController::HearTheMatch`), and "Reloading!" from a teammate within earshot (a reload's multicast says whether it is called out, at most once in six seconds a player, `ACheeseStrikeCharacter::TakeReloadCall`, `HearReloadCall`; never heard by the one reloading). Belica's ten a woman's, `Content/OpenGameArt/HurtFemale/`, the men's ten the others'; a bot's by the hero it wears, heard on the host's machine from where it is hurt), plainly over the gunfire, one of ten and never the same twice running, once for every ten health lost since the last (small hits adding up) and once for a burst of hits, and the one who hit a heavy, toneless thud near full scale (`CheeseStrikeSounds::ShouldOof`, `NextOof`, `OofVolume`; `CheeseStrikeSynth::Thump`); every sound made in code (`CheeseStrikeSynth`: the thud, the ka-ching, the siren, the explosions, the menu's) plays through a wave whose every playing ends with its samples (`UCheeseStrikeSynthWave`, `MakeSound`: a procedural wave fed through its queue, as they were until wave 16, never ends, and each held a voice playing silence until the voices ran out, which in a long match left the gunfire and the reloads, at 0.6 of the volume, losing every voice for good while the thuds played on; `CheeseStrike.QueuedSynth 1` makes them so again, to show it; `CheeseStrikeSoundsPlaying` logs the voices, `CheeseStrikeUISound` plays the menu's, `tools/play/ui_sounds.txt`); a weapon taken from a stand or the floor clacks where it is taken, one syllable of a reload (`MulticastPickedUp`, `CheeseStrikeSounds::PickupClackPath`: a bolt-action rifle's click-clack, 110 ms, with a low knock under it, made by `tools/art/wave16_sounds.py`, which makes the woman's grunts too; drawing a weapon in hand keeps Lyra's weapon swap); and a kill of one's own rings a cash register's ka-ching with the kill pop, an assist a softer ching (`ACheeseStrikePlayerController::HearScore`, `CheeseStrikeSynth::KaChing`). What the modes and streaks show over the view is drawn by `UI/CheeseStrikeModeHUD`, which the HUD calls. `CheeseStrikeGiveStreak <1-3> [name or enemy]` on the host's console gives one for looking at it (`tools/play/strike.txt`, `streaks.txt`, `elimination.txt`).
- **Movement is predicted.** Anything that changes how the character moves must reach the server through the saved move (`CheeseStrikeMovementComponent`): a held key as a compressed flag, state as fields saved and restored with the move. Otherwise the server disagrees with what the player saw and snaps them back.
- **Editing assets from a script.** The editor's Python runs headless: `UnrealEditor-Cmd.exe <project> -ExecCmds="py <script>" -unattended -nullrhi` with `unreal.SystemLibrary.quit_editor()` at the script's end (the `-run=pythonscript` commandlet can't save a map). `print` goes nowhere; write to a file. The editor must be closed first: it holds the game module and the open level's file. A script can't rebuild a material that a C++ constructor loads, directly or through what it loads (a mesh's materials and their parents): what is loaded at the editor's start is rooted for good, and deleting its expressions asserts; so a class whose assets the scripts rebuild holds them as soft references and loads them in `BeginPlay` (`ACheeseStrikeMouse`). Setting a slot of an array read with `get_editor_property` changes a copy: build new structs and set the array back.
- **Packaging and sharing.** `powershell -ExecutionPolicy Bypass -File tools/package.ps1` packages a Development build for Windows (`BuildCookRun`; not Shipping, which would have Steam relaunch it as the test app id's game), plays it twice headless to check it (`tools/play/packaged_*.txt`: the menus, then a match on The Creamery with bots and mice), zips it without its debug symbols (kept in `..\CheeseStrikeBuilds\symbols\`) and copies the zip into `G:\My Drive\CheeseStrike Builds`, which Google Drive for desktop uploads, keeping the newest three. Only the maps in `Config/DefaultGame.ini`'s `MapsToCook` are cooked, with what they and the code reach, so a new map goes in that list as well as in `CheeseStrikeRules::Maps`; an asset that C++ holds only as a soft reference or loads by a path built at runtime isn't cooked, so its folder goes in `DirectoriesToAlwaysCook` (the mice's rat and sounds), and files read as files rather than assets (the menu's `Content/UI/`) are staged by `DirectoriesToAlwaysStageAsUFS`. The packaged game compiles as a unity build, so names in one file's anonymous namespace meet every other file's: give them names no parameter will have (`MousePitch`, not `Pitch`), or the package fails where the editor's build didn't.
- **The compiler is pinned.** Both targets in `Source/*.Target.cs` build with MSVC 14.50.35717, which Unreal 5.8 is made for; the 14.51 that Visual Studio 2026 updates bring in breaks the engine's headers. Change it there when Epic supports a newer one.
- **Working on several things at once.** `python tools/worktree.py add <name>` makes another working copy at `C:\Hamid\code\cs-wt\<name>` on a branch of that name, its `Content/` a worktree of the assets submodule (sharing its history and LFS objects; never `git submodule update` there, but `git -C Content checkout <commit>`), and `remove <name>` deletes it. Each copy builds its own binaries, and its tests and played games keep to themselves: `tools/run_tests.py` and `tools/play.ps1` give each copy its own build id (`-BuildIdOverride`, so that matches on the local network are found only by the same copy) and `play.ps1` its own port; play tests in the editor listen on a port of the copy's own too (`PlayTesting.cpp`), since a match that travels listens again on the port it was first given. Close only the games and editors of the copy being worked in.
- **Building from the command line.** `"C:\Program Files\Epic Games\UE_5.8\Engine\Build\BatchFiles\Build.bat" CheeseStrikeEditor Win64 Development -Project="<repo>\CheeseStrike.uproject" -WaitMutex -NoHotReloadFromIDE`. The last option lets the build go ahead while a game or editor of another working copy (`tools/worktree.py`) runs with Live Coding on, which otherwise stops every copy's build (`tools/run_tests.py` passes it); a game or editor of this copy holds its module's DLL, so close it first, or build from inside it with Live Coding.
- **Assets are in a private submodule.** This repository is public; `Content/` is the private `cheesestrike-assets` repository, because most assets may not be redistributed (Epic's template content under the Unreal Engine EULA, Fab content under its licences). Never commit an asset to this repository. A change to assets is a commit in `Content/` (on its `main`, pushed first), then a commit here that moves the submodule to it, in the same pull request as any code it goes with. Add a row to `Content/LICENSES.md` for every pack or file brought in, with its source and licence, and keep the folder each pack came in (`Content/<Pack>/`); in the same change give it a line in the game's credits (`Source/CheeseStrike/UI/CheeseStrikeCredits.cpp`, the front end's Credits page), naming it as its licence asks: a Creative Commons Attribution work by its title, author and licence (`CheeseStrike.Project.TheCreditsNameEveryone` checks every linked title in such a row). A new clone needs `git submodule update --init`, then `git lfs pull` inside `Content/`. Without the submodule the code still builds, but the project has nothing to open and the tests that check content fail.
- **Git LFS.** Binary files go through Git LFS in both repositories (`.gitattributes`). Run `git lfs install` once on a new machine. Don't commit `Binaries/`, `Intermediate/`, `Saved/` or the Visual Studio files; `.gitignore` leaves them out.
- **Scale.** The world is life size: Unreal centimetres and a 180 cm player. The Godot game was three times life size; [docs/unreal/design.md](docs/unreal/design.md#scale) says how its numbers convert.
